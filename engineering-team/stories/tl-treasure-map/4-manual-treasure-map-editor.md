## Background
Stories 1–3 give the Treasure Map page a ratified TL-advertisement convention, a legible entries
panel, and the one-click opt-in. The operator wants an escape hatch for everything the derived
flow doesn't cover: edit the raw kind-10040 by hand and republish it — from the same panel,
in every state (the green "already local" state is precisely where the opt-in button is gone
but manual control still matters).

## User-facing description
As a signed-in user viewing my found Treasure Map, I want a hand-edit affordance at the bottom
of the Trusted Lists panel that opens my current raw event in an editable field and lets me
publish the edited version, so that I can make arbitrary Map changes without leaving the page.

## Acceptance criteria
- [ ] AC-1: A toggle button titled exactly "Update your kind 10040 event Treasure Map by hand"
      renders at the bottom of the panel in **all** states (local, absent, external).
- [ ] AC-2: Opening it shows the **current found event verbatim** (`id`/`sig`/`created_at`
      included — the raw event, not the derived opt-in preview) in an editable field.
- [ ] AC-3: A "Publish updated event" button appears **only once the text differs** from the
      original; while pristine there is no publish affordance.
- [ ] AC-4: Publishing parses the edited JSON and composes the unsigned replacement per the
      re-stamp policy: edited `kind`/`tags`/`content` honored exactly (kind defaults to 10040
      when absent); `id`/`sig` dropped (regenerated by signing); `created_at` re-stamped
      skew-proof (`max(now, old+1)`); `pubkey` from the drift-guarded signer — then NIP-07 sign
      + `publishOrThrow` (deployment publish gate inherited). Success re-runs the page's search.
- [ ] AC-5: Invalid input (malformed JSON; non-object; `tags` not an array of string-arrays)
      surfaces an error in the section without publishing; page state uncorrupted.
- [ ] AC-6: The opt-in flow above (three states, prompt copy, preview-above-button, publish) is
      unchanged.

## Design note *(Light profile — provisional here, ratified at Gate B)*
- **Chosen approach:** one pure helper + one section component. `composeManualUpdate(text,
  oldEvent)` in `ui/src/utils/treasureMap.js` (additive): parses the edited JSON, validates
  (object; `tags` an array of arrays of strings; `content` string when present), throws
  `Error` with a human message on violation, returns the unsigned `{kind, tags, content,
  created_at: max(now, old+1)}` — the caller adds `pubkey` from the signer.
  `ManualEditSection` (module-level component inside `TlOptInCard.jsx`) with own state
  (`open`, `text`, `error`, `publishing`); baseline = `JSON.stringify(event, null, 2)` seeded
  on open; dirty = text ≠ baseline gates the publish button; publish chain reuses
  `getActiveSignerOrThrow` → `window.nostr.signEvent` → `publishOrThrow`; mounted at the bottom
  of **both** card branches with `key={event.id}` so a refreshed event re-seeds the editor.
- **Rejected alternative:** reuse the opt-in preview surface for editing — rejected: the
  preview renders the *derived* update (read-only concern) while the editor edits the *found*
  event; conflating the two invites publishing a half-derived object, and their error states
  differ.
- **Blast radius:** `ui/src/utils/treasureMap.js` (additive export) and
  `ui/src/pages/grapevine/TlOptInCard.jsx`. `TrustedAssertions.jsx`, the story-2 panel, and the
  consumed publish utils untouched.
- **Wire fidelity:** no new wire decisions — the published object is whatever the user wrote,
  under ADR-0001-adjacent replaceable-event mechanics (fresh `created_at`, signer identity)
  already ratified for story 3.

## Edge cases & not-covered
- **E1 (not derivable from any AC):** a successful opt-in publish (or any re-search) swaps the
  found event **while the editor is open** — the section is keyed on `event.id`, so it re-seeds
  from the new event and deliberately discards stale edits, rather than publishing edits
  composed against a Map that is no longer current.
- E2: `kind` deleted in the edit → defaults back to 10040 (AC-4), never `undefined`.
- E3: whitespace-only reformat (same JSON, different text) counts as dirty — the gate is
  textual, not semantic; publishing a reformat is harmless (re-stamped replacement).
- E4: `tags: []` is valid (an emptied Map publishes; the relay replace rule applies) — the
  editor does not second-guess destructive-but-well-formed edits.
- **Not covered:** NIP-07 extension UI; live relay sockets (same boundaries as story 3);
  JSON-schema-grade validation beyond the object/tags/content checks (the signer and relays are
  the final arbiters); logged-in browser flow (B-class, operator at Gate B).
