# ADR 0001: Goal capture adopts the existing element machinery; the Goals view reads through a new owner-gated brain endpoint

**Status:** Accepted
**Date:** 2026-07-22
**Story:** `engineering-team/stories/second-brain/1-capture-a-goal-and-see-it.md`

## Context

The story: the owner states a goal in conversation and sees it in a Goals view inside the owner-gated control panel. Six ACs — conversational capture recorded with name/statement/origin/capture-date + one-sentence confirmation; the goal rendered with standing word `captured`; the three pre-existing goals adopted; verbatim cold-start empty state; verbatim privacy indicator; zero banned jargon. The PRD's §7 Policy Constitution binds (notably §7.7 plain language, §7.8 adopt-don't-re-derive); the design/style guides and wireframes are review-binding.

Facts established by recon against the live local stack (2026-07-22) and the source:

- **The concept is runtime-created, not firmware-seeded.** `39998:<TA>:tapestry-owner-goal` exists on this instance only (created 2026-07-18 via `POST /api/normalize/create-concept`); `grep -rl tapestry-owner-goal firmware/` is empty. Consequence: firmware reinstall **cannot clobber its schema** (install passes 1/2 iterate only `manifest.concepts` — `src/firmware/install.js:208,880`), and pass 1d/3c *re-derive* the superset→element `HAS_ELEMENT` wiring from each element's `z` tag (`install.js:594-639`) — protective for goal elements. Other deployments (staging, droplets, a second operator) do not have the concept at all until it is bootstrapped there.
- **The element write path already exists.** `POST /api/normalize/create-element` (`src/api/normalize/index.js:1760-1891`, route `:3306`): resolves the concept by name, requires its Superset, dedup-checks the class thread, mints a kind-39999 event (tags `d`/`name`/`z=<header uuid>`/`json`), signs with the runtime TA key (`loadTAKey` → `getOwnerAssistantKeys`, `:88-113`), publishes to **local** strfry via `strfry import`, imports to Neo4j, and MERGEs `HAS_ELEMENT` through the firmware alias layer. Deterministic d-tag `slug(name)-1903378a` (hash8 of the header uuid — matches all three live goals). No write-time schema validation; caller json is stored verbatim.
- **The live goal record shape** is a `json` tag `{"tapestryOwnerGoal":{"name","slug","description"}}`; the schema element (`39999:<TA>:tapestry-owner-goal-schema`) requires exactly `[name, slug, description]`, no `additionalProperties:false`. `POST /api/normalize/save-schema` wholesale-replaces the schema (complete resend required) and re-signs the same d-tag; it does **not** update the primary-property node (documented drift). `ui/src/pages/concepts/ElementDetail.jsx:123-167` extracts only schema-declared keys and shallow-merges on save — **undeclared nested fields are silently dropped on any owner edit**.
- **The 3-vs-5 "stray" mystery is edge direction.** `elementCount: 3` comes from a *directed* Cypher (`src/api/concept-graph/index.js:29-33`); the neighbors endpoint matches undirected and erases direction (`:99-122`). The two "strays" (`set-superset`, `superset-superset`) are **incoming** edges — the goal superset is itself an element of the `set` and `superset` concepts, which is correct class-thread data, not pollution. They carry the `Superset` label; a directed walk structurally never sees them. (The header-side `HAS_ELEMENT` → `concept-header-superset` irregularity remains story 2's inventory to reconcile.)
- **No bulk elements-with-json GET exists.** The UI convention is client-authored Cypher via `POST /api/neo4j/query` (reads open — on deployed instances *unauthenticated* reads reach goal content; ADR `security-auth-exposure/0001` residual). The canonical one-query pattern is `ConceptElements.jsx:68-85` (directed downward walk ∪ implicit z-tag members, json tag collected — no N+1).
- **No conversational surface exists in this codebase** (no chat route, no MCP; the design guide bans an agent-chat UI). "In conversation" means an agent session (Claude Code / openclaw per AGENTS.md) or the owner's browser session. Agents reach owner-gated APIs via container-loopback (`docker exec tapestry curl http://127.0.0.1:7778/...` → `req.localTrusted`, `src/middleware/auth.js:324-338`). New mutations are default-denied for sessionless callers; authenticated **non-owners** are stopped only by an explicit in-handler gate `if (!isOwner(req) && !req.localTrusted) return 403` (the wipe.js/relationships.js pattern; route-level `requireOwner` would 401 the loopback agent).
- **Privacy.** Goal events in local strfry do **not** leave the machine under the live router config (every enabled kind-39999 stream is `#z`-filtered to the five legacy tag handles; the goal z-tag matches none — verified in `/etc/strfry-router-tapestry.config` + `router-state.json`). But it is convention, not mechanism: the dormant `dcosl` preset (all 39998/39999, dir=both), the ConceptDetail "publish to community" button, and negentropy up-sync are the three owner-actionable escape hatches. `ui/src/utils/nostrPublish.js` `publishEverywhere` fans out to five hardcoded production relays (event-tagging ADR 0002, fail-open). PRD §7.4 explicitly rules v1 privacy a *stated convention*; mechanism is Phase 2.
- **UI shell.** Control-panel pages nest under the `/tapestry` route (`ui/src/App.jsx:197-201`, `Layout.jsx`); nav is data-driven with an existing-but-unused `ownerOnly` filter (`Layout.jsx:173`). Owner gating idiom: `user?.classification === 'owner' || user?.classification === 'admin'` (client, defense-in-depth) + server enforcement. Full-page-gate precedent: `pages/settings/Index.jsx`. Fetch idiom: plain hooks with AbortController; skeleton: `.bsp-skeleton-row` + `bsp-shimmer` (`styles.css:7547-7561`). **Token mismatch:** the guide/wireframes name `--surface/--surface-2/--radius/--space-*`, which do not exist in `styles.css` (`--bg-secondary`/`--bg-tertiary` do; no radius/space tokens). No jsdom/testing-library exists; UI logic that needs real tests lives in pure ESM cores (graph-curation-ui ADR 0001 pattern).

Binding prior ADRs: `security-auth-exposure/0001+0002` (caller classes, default-deny, per-endpoint gates), `relationship-primitives/0001+0002` (alias-resolved relationship types; `relationships.js` and the probe are byte-pinned — untouched), `event-tagging/0002` (never route through `publishEverywhere`), `event-tagging/0009` (read-time normalization, pure cores, no denormalized subjective flags), `test-hermeticity-ci/0001` (U/S/H test classes), ADR 0015 (legacy z-tag exception does not touch the goal stack — runtime TA everywhere here).

## Options considered

### Option A — Adopt `create-element` for capture; new server-side owner-gated read (`/api/brain`); extend the concept schema with optional fields

Capture = the conversational agent (or owner session) calls the existing `POST /api/normalize/create-element` with a goal-shaped body; no new write endpoint. Read = one new small module `src/api/brain/` exposing `GET /api/brain/goals` over a pure core `src/lib/brain/goals.js`. The concept schema gains **optional** `origin` and `capturedOn`; the PRD's "statement" **is** the existing `description` field (adopt, don't duplicate).

- **Pros:** honors §7.8 verbatim (both the concept *and* the write machinery are adopted); one write path keeps strfry+Neo4j consistent (dedup, deterministic d-tag, z-tag wiring that reinstall re-derives protectively); the schema extension makes the convention discoverable in-graph (§5.9 second-operator guard) and survives owner edits (ElementDetail drops only *undeclared* fields); the server-side read gives story 2's checker a shared classification core, avoids N+1, and is the single seam where Phase-2 privacy mechanism can land; the directed-walk filter excludes the strays structurally rather than by name.
- **Cons:** capture rides a 3,300-line composite module with a known adjacent bug (publishToStrfry can report success on a silent strfry drop — intake 2026-07-x); the H-class capture test must therefore assert **read-back**, not response success. The read endpoint is a new surface to maintain.

### Option B — Dedicated brain write endpoint (`POST /api/brain/capture-goal`) per the relationship-primitives template

A new strfry-aware capture primitive with discriminated results, plus the same read endpoint.

- **Pros:** a purpose-built conversational contract; the relationship-primitives ADR names its module the template for "the planned family of second-brain primitives."
- **Cons:** re-derives what `create-element` already does (mint/sign/publish/import/wire/dedup) — a second element-creation path to keep consistent forever, contra §7.8; the "primitives family" argument fits *missing* primitives (single-edge ops), not an existing composite that matches the need exactly. Rejected now; revisit when a brain-specific write contract genuinely diverges (story 5's append-only work records are the likely first case).

### Option C — Client-side reads via `useCypher` raw Cypher (the incumbent concept-page pattern), no new server code at all

- **Pros:** smallest diff; matches ConceptElements/ConceptList today.
- **Cons:** story 2's repeatable checker can't share the classification; couples the owner surface to raw client Cypher against the open read endpoint (the deployed-instance unauthenticated-read residual grows a new consumer); no seam for Phase-2 privacy hardening; the strays/direction subtlety gets re-implemented in JSX where it can't be unit-tested (no jsdom). Rejected.

## Decision

We chose **Option A**.

Sub-decisions, each binding:

1. **Capture contract** (documented here; story 5 makes it agent-discoverable): `POST /api/normalize/create-element` with body
   `{"concept": "tapestry owner goal", "name": <goal name>, "json": {"tapestryOwnerGoal": {"name": <name>, "slug": <slug(name)>, "description": <the owner's statement>, "origin": <plain phrase, e.g. "owner, in conversation">, "capturedOn": <ISO-8601 date>}}}`
   Callers: container-loopback agent (`req.localTrusted`) or owner session. The one-sentence confirmation (*"Goal captured."*) is uttered by the conversational agent — API responses are not owner-facing. On a fresh instance the idempotent bootstrap is: `create-concept` (name `tapestry owner goal`, the PRD §6 description) → `save-schema` (complete schema below) → `create-element`. The read endpoint never auto-provisions (reads don't mutate — event-tagging 0009).
2. **Field mapping:** statement ≡ `description` (adopted, displayed under plain labels); `origin` and `capturedOn` are **new optional** schema fields (optional keeps the three legacy elements valid under advisory ajv). `capturedOn` is an ISO-8601 date string stored in the json blob — the event's `created_at` is *not* the capture date (re-signs via `regenerateJson` reset it); for legacy elements missing `capturedOn`, display falls back to `created_at`. One-time per-deployment `save-schema` call applies the extension (complete schema resend; local now, other instances at their bootstrap). Primary-property node drift is accepted and recorded (see Consequences).
3. **Read surface:** `GET /api/brain/goals` in new `src/api/brain/index.js`, registered in `src/api/index.js`, with the in-handler gate `if (!isOwner(req) && !req.localTrusted) return 403` (platform template — admits admin sessions, consistent with every owner surface in the panel; owner-only tightening is the prd-seed §7 open product question, Phase 2). Resolves the TA pubkey at runtime (`getOwnerAssistantPubkey()`), builds the header handle, runs **one** Cypher: directed downward walk (`(h)-[:IS_THE_CONCEPT_FOR]->(s:Superset)-[:IS_A_SUPERSET_OF*0..10]->()-[:HAS_ELEMENT]->(e:NostrEvent)`) **∪** implicit z-tag members, collecting each element's `json` tag — the `ConceptElements.jsx:68-85` canonical pattern via `runCypher`. Concept absent → `{success:true, goals:[]}` (an empty brain is a state, not an error — §5.9). Response goals: `{uuid, name, statement, origin, capturedOn, createdAt, standing}`.
4. **Pure core** `src/lib/brain/goals.js` (ESM, dependency-free): json-blob parsing → goal record; `deriveStanding()` (returns `captured` for every v1 record — the derived-not-stored extension point stories 3/6 grow); capture-date resolution (capturedOn ∥ created_at); sort **capture date descending** (interpretation — no order is specified in guide or wireframes). Story 2's checker imports this core.
5. **UI:** route `/tapestry/goals` as a `/tapestry` Layout child (crumb `Goals`); nav entry in `mainNavItems` with `ownerOnly: true` (first consumer of the existing `Layout.jsx:173` filter); full-page gate mirroring `settings/Index.jsx` (authLoading → gate → content); plain fetch hook `useBrainGoals` (AbortController; refetch on window focus/visibility + a light poll while visible so the design guide's 2-second new-row highlight fade is honest). Rows: name (600) + standing word `captured` (muted small caps); chip and pointer-count metadata are data-driven and render only when the data exists (none in v1). Rows do **not** navigate in story 1 (the detail page is story 4; routing to ElementDetail would put banned vocabulary on an owner surface). The viability hint line is **story 3's AC**, not rendered here. Cold-start copy is the style guide's canonical sentence **exactly** (where the wireframe embellishes, the style guide is the copy authority). Privacy line verbatim, static, bottom of the view. Loading: three `.bsp-skeleton-row`-pattern rows; error: inline plain-language line with accent retry link.
6. **Token/shell ruling:** guide names map to real tokens — `--surface` ≡ `--bg-secondary`, `--surface-2` ≡ `--bg-tertiary`; radius/spacing are written as literal CSS in `styles.css` new `.brain-*` classes consistent with app idiom (no new `:root` tokens, honoring the guide's own no-new-tokens rule; the guide's `:root` block was copied from the wireframe's self-contained stylesheet, not from the app). Shell = Layout `.main-content` + `page` idiom (the guide's "inside the owner-gated control panel" governs; its `.bsp-content` citation is read as spacing rhythm, not the visitor-page shell).
7. **Privacy posture:** capture writes local strfry only via server-side machinery; nothing in this story imports or routes through `ui/src/utils/nostrPublish.js`; the goal z-tag stays outside every outbound router stream (current config verified). The indicator is honest as a statement of the PRD's declared v1 convention. The three escape hatches (dcosl preset toggle, concept-publish button, negentropy up-sync) are documented risks, untouched here; a dynamic/withdrawing indicator is a Phase-2 product question.

## Consequences

- **Enables:** capture-to-view end-to-end with ~2 new server files, 1 hook, 1 page, and zero new write endpoints; stories 2–8 inherit a brain API seam, a shared pure classification core, and a schema whose optional-field pattern extends to deliverable/boundary/parent/category (story 3) without re-signing existing elements.
- **Constrains:** the Goals tree must keep rendering from record-based data (flat in v1) — never from an edge walk — so story 3 retains the HAS_SUBGOAL materialization choice (whitelist extension path, relationship-primitives 0001). Story 4's row-click wiring lands in a view that deliberately has no navigation stub to fight.
- **Debt / follow-ups:** (a) primary-property node drift after `save-schema` — recorded for story 2's hygiene inventory (alongside reconciling the queue's stray-edge list against the direction findings: the superset-side pair is legitimate incoming data; the header-side edge is the real irregularity). (b) The publishToStrfry silent-drop bug remains open on the normalize surface (pre-existing intake); this story mitigates by read-back assertion, not by fixing it. (c) Deployed-instance unauthenticated read-Cypher residual now also exposes goal content — accepted under the PRD's convention posture; Phase-2 mechanism is the named fix. (d) Router-toggle reachability for authenticated non-owners (pre-existing follow-up, intake 2026-07-21) is what could silently falsify the privacy line — noted there, not fixed here.
- **Firmware reinstall required?** **No.** The concept is runtime-created (not firmware-seeded); the schema extension is a live-graph `save-schema` call. Installer behavior untouched (operator decision 2026-07-18).

## Implementation notes

- File: `src/lib/brain/goals.js` — **new**, pure ESM, dependency-free. Exports ≈ `parseGoalRow(row)` (uuid/name/json-string → record `{uuid, name, statement, origin, capturedOn, createdAt}`; tolerant of missing/malformed json — a row that isn't a parseable goal record is classified out, with the row returned in a `rejects` list for story 2's checker), `deriveStanding(record)` → `'captured'`, `resolveCaptureDate(record)`, `sortGoals(records)` (capture date desc). No React, no fetch, no Neo4j imports.
- File: `src/api/brain/index.js` — **new**. `registerBrainRoutes(app)`; `GET /api/brain/goals`: in-handler gate (`isOwner(req) || req.localTrusted` → else 403 `{success:false, error}`), TA via `getOwnerAssistantPubkey()`, one `runCypher` (union query per Decision 3, parameterized), map rows through the core, respond `{success:true, goals}`. Concept-absent/empty → `{success:true, goals:[]}`. No mutations, no strfry access, no imports beyond `lib/neo4j-driver`, `middleware/auth` (isOwner), `utils/assistantKeys`, `lib/brain/goals` — keep the import surface S-testable.
- File: `src/api/index.js` — register `registerBrainRoutes` (mount comment: the second-brain read surface).
- File: `ui/src/hooks/useBrainGoals.js` — **new**: `{goals, loading, error, refetch}`; AbortController (`useGrapevineFollows.js` pattern); focus/visibility refetch + interval poll (~20s) while visible.
- File: `ui/src/pages/brain/Goals.jsx` — **new**: settings-style gate; states per Decision 5; new-row highlight (2s fade via `--bg-tertiary`); verbatim strings from the style guide — cold start *"Your brain is empty — that's the right place to start. Tell your assistant a goal in plain words and it will appear here."*, privacy line *"This brain stays on this machine — nothing here is published."*; view title `Goals`.
- File: `ui/src/App.jsx` — child route `{path: 'goals', element: <Goals/>, handle:{crumb:'Goals'}}` under `/tapestry`.
- File: `ui/src/components/Layout.jsx` — `mainNavItems` entry `{label:'Goals', to:'/tapestry/goals', ownerOnly:true}` (placement: near the top; exact position is the Implementer's call).
- File: `ui/src/styles.css` — `.brain-*` classes per Decision 6 (row min-height 44px, 8px-scale paddings, existing token vars only).
- **Operational step (not code, journaled at implementation):** the one-time local `save-schema` extension call (complete schema: existing `name`/`slug`/`description` + optional `origin`, `capturedOn`; `x-tapestry.unique` unchanged). The exact curl and full schema JSON go in the implementation notes/test setup so the bootstrap sequence is copy-runnable for other deployments.
- **Untouchables:** `src/api/normalize/relationships.js`, `src/api/normalize/probe.js` (byte-pinned by S-tests), the four `LEGACY_*` files (ADR 0015), `PUBLIC_MUTATIONS`, firmware/installer.
- Test-class guidance (Tester's lane to specify): U = core functions; S = source assertions (gate present in `brain/index.js`; import surface exact; verbatim copy strings present; banned-word scan over the new owner-facing strings; no `nostrPublish` import anywhere in the new UI files); H = live (GET returns the three legacy goals with `standing:'captured'`; capture round-trip — `create-element` with the contract body then **read-back** via the GET; authenticated-non-owner 403 if session simulation is feasible, else localTrusted-absence semantics per the relationship-primitives precedent). JSX compile: reviewer's in-container `vite build` (established gap-filler).
