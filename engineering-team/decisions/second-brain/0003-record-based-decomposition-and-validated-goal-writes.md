**Status:** Accepted
**Date:** 2026-07-23
**Story:** `engineering-team/stories/second-brain/3-break-a-goal-into-pieces.md`
**Amended by:** ADR 0004 (d11's interim read-path — "no new API; the detail page selects from the list read" — superseded by the per-goal endpoint `GET /api/brain/goals/:slug`).
**Amends:** second-brain ADR 0002 — d4's schema-object resolution phrasing ("sole top-level *required* key" → the implemented and hereby-ratified "sole top-level *properties* key"), and Consequences (a)'s paired-reconcile requirement (dissolved by d8 below for the save-schema path). ## Context

The story: in conversation, a goal acquires child goals (one parent each, a tree); a leaf with both a deliverable ("done means") and a boundary ("stays inside") derives standing `viable`; a goal with children never does; the Goals view renders the nesting with disclosure; a minimal Goal detail shows the two fields labelled verbatim. Adoption (setting a parent on an existing *parentless* goal) is gate-ratified in scope; self-parenting, cycles, and dangling parents are refused loudly with nothing written. Standing stays derived at read time. Hygiene must end the story green.

Facts established at planning/architecture recon (live instance + source, 2026-07-23; TA `11f23fe4…` runtime-resolved throughout; adversarial design review run before this gate):

- **Live baseline:** three goals, all top-level `captured` leaves (`origin`/`capturedOn` null on all three — legacy captures); hygiene green (3 + 5 elements). Schema (`39999:<TA>:tapestry-owner-goal-schema`) declares `tapestryOwnerGoal` with required `[name, slug, description]`, optional `origin`, `capturedOn`, `x-tapestry.unique: [name, slug]`. The json `slug` field (e.g. `nosfabrica-success`) is instance-portable; the d-tag (`nosfabrica-success-1903378a`) embeds hash8 of the header uuid and is therefore TA-bound.
- **`x-tapestry.unique` is advisory only** — no server code enforces it; ajv validation is client-side and display-only (`ui/src/pages/concepts/ElementDetail.jsx:183-202`). Uniqueness must be enforced by whatever endpoint cares.
- **Name collisions silently replace.** `create-element`'s dedup is exact-trimmed-*name* match within the concept subtree (`src/api/normalize/index.js:1789-1798`), but the d-tag is `dtag.childDTag(name, headerUuid)` = `slug(name)-hash8(headerUuid)` (`src/lib/dtag.js:51-54`) where `slug()` lowercases and strips punctuation/diacritics — and `headerUuid` is the *concept* header, identical for every goal. Two names that differ only in case/punctuation ("Ship It" / "ship it") pass name-dedup yet derive the **same d-tag, hence the same uuid**; `importEventDirect` MERGEs on uuid (`:142-176`) and strfry treats kind-39999 as replaceable — the second create **overwrites the first goal** with `success:true`. Any slug-referencing design must close this.
- **The pure core whitelists fields.** `parseGoalRow` builds a fresh record from exactly `name`/`description`/`origin`/`capturedOn` (`src/lib/brain/goals.js:24-42`) — unknown json fields are dropped, and the record has no `slug`. `deriveStanding(_record)` returns `'captured'` unconditionally and is the documented single extension point (`goals.js:44-52`). Nothing in either core understands parent/child; cross-goal checks need the full record set.
- **The brain module is structurally read-only and its import surface is double-pinned.** Story-1 S2 + story-2 S3 pin `src/api/brain/index.js` to exactly five require *specs* (`test/capture-a-goal-and-see-it.test.js:331`, `test/structures-the-brain-can-trust.test.js:451`) — new destructured names from the same requires do not trip them; story-2 S6 forbids mutation/strfry tokens in the module (`…test.js:486-493`). A write path cannot live there.
- **Normalize's write machinery is module-internal.** `module.exports = { registerNormalizeRoutes }` is the sole export (`src/api/normalize/index.js:3449`); `regenerateJson` (:56), `signAndFinalize` (:105), `publishToStrfry` (:115), `importEventDirect` (:135), `dtag` are callable only from inside the module. The gated-write precedent is `handleReconcilePrimaryProperty` (:1990-2079): in-handler gate, lazy requires of `middleware/auth` and `lib/brain/hygiene`, discriminated results, `regenerateJson` for the write. Story-2 S4 pins the mechanism tokens (`regenerateJson(`, `'already-consistent'`, `'reconciled'`) *inside that handler's body slice* (`test/structures-the-brain-can-trust.test.js:459-474`) — any extraction must re-aim S4.
- **`regenerateJson` re-signs with a fresh `created_at`** (`signAndFinalize`, :109; `importEventDirect` :145,154). For the three legacy goals (`capturedOn: null`), `resolveCaptureDate` falls back to `createdAt` — so any update that re-signs a legacy goal would silently move its displayed capture date to today unless `capturedOn` is backfilled first.
- **`handleSaveSchema` (:1899-1973) regenerates only the schema node.** ADR 0002 Option C — folding primary-property regeneration into `save-schema` — was explicitly deferred to this ADR. The fold point is between `regenerateJson(schemaUuid, …)` (:1961) and the response. **Reach of the fold:** firmware install pass 2 calls `save-schema` for every firmware concept (`src/firmware/install.js:962`, reading only `success` from the response, :967) — whatever the fold does happens at every install, for all 44+ concepts.
- **Auth:** a new POST under `/api/normalize/*` is 401'd for sessionless remotes by default-deny (`src/middleware/auth.js:442-457`) *and* 403'd for authenticated non-owner/admin sessions by the `ownerOnlyEndpoints` substring list (:397, :417-419, :433-437); loopback agents pass via `req.localTrusted` (:324-338); the in-handler gate template `if (!isOwner(req) && !req.localTrusted) return 403` admits owner + admin sessions + loopback (`isOwner` ≡ `isOwnerOrAdmin`, :250-267). GETs under `/api/brain/*` are protected by nothing but their in-handler gates.
- **UI:** `Goals.jsx` renders flat rows (name + standing only), no navigation, no router import; story-1 S5b bans the tokens `toggle|checkbox|switch` (case-insensitive) from the whole file (`test/capture-a-goal-and-see-it.test.js:371-376`); story-1 S7 bans the words `viable`/`achieved`/`abandoned` from it (:385-394); story-1 S8's jargon scan covers `Goals.jsx` only; **story-1 H1 asserts every goal in the live response has `standing === 'captured'`** (:468-471) — the feature's success falsifies that invariant permanently. `useBrainGoals` polls a fixed URL. Parameterized-detail precedent: `grapevine/trusted-lists/:dTag` → `TrustedListDetail.jsx` (flat leaf route, `useParams`, loading/error/not-found branches); `.brain-*` classes at `styles.css:8168-8181`. The wireframe's detail (§2) opens with a "← Goals" back link and its metadata line reads `viable · engineering · part of "Typo-tolerant search" · captured Jul 20 by you` (`second-brain-wireframes.html:91-95`).
- **`HAS_SUBGOAL` is frame-excluded:** the shipped whitelist rejects net-new types; extension is the relationship-primitives book's documented post-book path requiring a cardinality-safety design. ADR 0001's Consequence stands: the Goals tree renders from record-based data, never from an edge walk.
- Row 85's notes fall due here: (a) reconcile's properties-key resolution vs 0002 d4's phrasing (see **Amends**); (b) the reconcile's read-compare-write race, erased for the save-schema path by d8; (c) unreadable *schema* reported under `property-record-drift`; (d) incoming `HAS_ELEMENT` from a non-Superset node silently ignored (`hygiene.js:92-96`).

Binding prior ADRs: second-brain 0001 (adopt element machinery; brain read seam; derived-not-stored standing; record-based tree) and 0002 (read-only brain module; taxonomy changed deliberately; Option C scheduled here); relationship-primitives 0001+0002 (`relationships.js`/`probe.js` byte-pinned, whitelist untouched); event-tagging 0002 (never `publishEverywhere`) and 0009 (derive at read time, no stored subjective flags); security-auth-exposure 0001+0002 (explicit gates on new mutations); test-hermeticity 0001 (U/S/H classes); ADR 0015 (legacy files untouched).

## Options considered

### Option A — Decomposition as optional fields on the goal record; two validated, gated, serialized write primitives in normalize; Option C folded into save-schema; standing derived in the shared core

The goal record (json `tapestryOwnerGoal` section) gains three **optional** fields — `deliverable`, `boundary`, `parent` — via the ADR 0001 d2 schema-extension pattern. `parent` is the **parent goal's json `slug`** (instance-portable; survives re-signs and export/restore, unlike the TA-bound d-tag/uuid) — with uniqueness *enforced at the new write path*, since nothing else enforces it. Two new write primitives land in `src/api/normalize/index.js` beside the reconcile, riding the module's internal machinery with all validation before any write: `create-child-goal` and `update-goal-intent`. `handleSaveSchema` folds in primary-property reconciliation (Option C). The pure core grows `resolveDecomposition(records)` and a children-aware `deriveStanding(record, context)`; the hygiene taxonomy grows four kinds. The brain module's Cypher and import surface are **unchanged** — new behavior arrives through new exports of the two already-required cores.

- **Pros:** honors every standing constraint by construction — record-based tree (0001), read-only brain module (S2/S3/S6 pins untouched), writes beside the machinery they ride (0002's reconcile precedent), refusal semantics enforced server-side where the AC demands them; slug refs keep story 8's export/restore and the second-operator guard honest; the collision refusal closes a pre-existing silent-overwrite hazard for goals; Option C kills the drift class at the write path and erases the row-85b race for the schema-extension flow; the check and the view share one classification/derivation truth; the three legacy goals stay valid.
- **Cons:** two more endpoints on an already large composite module; ~30 lines of concept-resolution Cypher duplicated from `create-element` (its logic is inline; refactoring the 3,300-line module's main path is declined); name/slug dedup is concept-wide, so two different parents cannot each have a child with the same name (recorded, acceptable v1); direct `create-element`/`save-element-json` calls can still write unvalidated fields — mitigated by read-time tolerance and detected by the grown taxonomy; the save-schema fold reaches firmware install (disclosed and scoped in d8).

### Option B — Materialize the tree as HAS_SUBGOAL edges

Extend the relationship whitelist, wire parent-child as typed edges, walk them for the tree.

- **Cons (dispositive):** the story, queue, and PRD §7.9 all exclude it — whitelist extension is the relationship-primitives book's post-book path and needs its cardinality-safety design first; ADR 0001's Consequence binds the tree to record-based data; edges are not durable intent (PRD §6 puts decomposition position in the goal's own record) and would not survive export/restore; firmware pass 1d knows nothing of custom edges. Rejected without reaching pros.

### Option C — No new write surface: ride create-element + save-element-json, validate in the conversational agent, detect drift via hygiene

- **Pros:** zero new endpoints; smallest diff.
- **Cons:** AC 1's "refused loudly, with nothing written" becomes agent goodwill, not system behavior; it builds the contract on the **ungated, validation-free** `save-element-json`/`set-json-tag` escape hatches (flagged security debt); the name/d-tag silent-overwrite hazard stays open on the exact path the contract would bless; refusal paths untestable as system behavior. Rejected.

## Decision

We chose **Option A**.

Sub-decisions, each binding:

1. **Record shape.** The `tapestryOwnerGoal` section gains optional `deliverable` (string — what done produces, in the owner's words), `boundary` (string — what pursuing this goal may not touch), `parent` (string — the `slug` of the parent goal). Statement stays ≡ `description` (0001 d2). The record parser extracts `slug`, `deliverable`, `boundary`, `parent` alongside the existing fields; record shape becomes `{uuid, name, slug, statement, origin, capturedOn, createdAt, deliverable, boundary, parent}`. All three legacy goals remain valid (fields optional; ajv advisory).
2. **Parent reference = json slug; the new endpoints are the uniqueness enforcement point.** Slug is unique-by-intent (`x-tapestry.unique`), instance-portable (no TA material — export/restore and second-operator safe), and stable across re-signs; but the annotation is advisory, so `create-child-goal` *enforces* it at write time (d6's `name-collides` refusal — which simultaneously closes the pre-existing same-d-tag silent-overwrite hazard for goals created through this contract). The json slug is derived with **`dtag.slug(name)`** (the diacritic-stripping variant, `src/lib/dtag.js:23-29`) so it always equals the d-tag base — pinned here because create-element's auto-json path uses a non-stripping variant and divergence would weaken slug-as-reference. Consequence recorded: a future rename flow must hold `slug` fixed (name-only rename) or re-write children's `parent` refs; that flow remains deferred.
3. **Standing derivation** (the 0001 d4 extension point, grown in place): `deriveStanding(record, context = {})` — `context.hasChildren === true` → `'captured'`; else if `record.deliverable` and `record.boundary` are both non-empty (trimmed) strings → `'viable'`; else `'captured'`. `achieved`/`abandoned` remain unreachable until later stories record such dated facts. Derived at read time on every call; never stored. One-argument calls keep returning `'captured'` for story-1-era records (story-1 U rows unaffected).
4. **Decomposition resolution in the shared core.** New `resolveDecomposition(records)` in `src/lib/brain/goals.js` (pure, dependency-free): builds a slug index — **duplicate slugs resolved deterministically: oldest `createdAt` wins, shadowed records flagged `slugShadowed: true`** — and annotates each record with `parentUuid` (the uuid of the winning record its `parent` slug resolves to, else `null`) and `hasChildren`. **Read-tolerant by construction:** a dangling `parent` resolves to root (`parentUuid: null`, `parentUnresolved: true`); a cycle (out-of-contract writes only, once d6/d7's serialization lands) is broken deterministically by nulling the parent links of the **cycle members only** — each becomes a flagged root and their descendants re-resolve normally, so subtrees render intact and rendering never loops and never hides a goal. One resolution truth for the API, the view, and the hygiene check. New `validateDecompositionOp(records, op)` (same file) returns the refusal for a proposed write: `parent-not-found`, `ambiguous-slug` (the referenced slug matches more than one record), `self-parent`, `cycle` (target parent lies inside the goal's own subtree), `already-has-parent` (adoption is for parentless goals only), else ok — U-testable with synthetic records.
5. **Read surface** (`GET /api/brain/goals`, shape extended additively — no Cypher change, no new requires): handler calls `resolveDecomposition` after parsing, then projects each goal as `{uuid, name, slug, statement, origin, capturedOn, createdAt, standing, captureDate, deliverable, boundary, parent, parentUuid, hasChildren}` with `standing: deriveStanding(r, {hasChildren})`. Ordering stays `sortGoals` over the whole set (capture date desc); the UI groups by `parentUuid` preserving that order, so root order and sibling order are both capture-desc. Story-1/2 H-suite snapshots read named fields and are unaffected by additive keys (verified against every consumer: `useBrainGoals`, story-1 H rows, story-2 `goalSetSnapshot`).
6. **Write primitive: `POST /api/normalize/create-child-goal`** in `src/api/normalize/index.js` (registered in `registerNormalizeRoutes`; the reconcile handler's idiom: in-handler gate first — `isOwner(req) || req.localTrusted` — then lazy-require what the handler needs). Body `{parent: <slug>, name, statement, deliverable?, boundary?, origin?, capturedOn?}`. Input validation first: 400 for missing/empty `parent`, `name` (trimmed), or `statement`. Flow, all checks before all writes: resolve the goal concept (create-element's lookup Cypher, duplicated locally); fetch the goal record set (the brain read queries' union, via `runCypher`); `validateDecompositionOp` (`parent-not-found` / `ambiguous-slug`); **collision refusal `name-collides`**: refuse if the element name matches an existing goal (create-element's name-dedup) *or* `dtag.slug(name)` collides with any existing record's `slug` or d-tag base — nothing written on any refusal; then mint the element precisely as `create-element` would — `dtag.childDTag(name, headerUuid)`, tags `d`/`name`/`z=<headerUuid>`/`json` with section `{name, slug: dtag.slug(name), description: statement, origin?, capturedOn?, deliverable?, boundary?, parent}` — `signAndFinalize` → `publishToStrfry` → `importEventDirect` → `:ListItem` label + slug property → `MERGE` the membership edge. Absent optional fields are omitted (not stored as empty strings). Discriminated results: `{success:true, result:'created', element:{uuid, name, slug, parent}}`; refusals are loud, named, HTTP-200 `{success:false, error}`.
7. **Write primitive: `POST /api/normalize/update-goal-intent`** (same file, same gate idiom). Body `{goal: <slug>, deliverable?, boundary?, parent?}` — at least one field required (400 otherwise); supplied values must be non-empty after trim (named refusal `empty-value` — clearing is out of scope and an empty-string backdoor would be clearing). Flow: resolve concept; fetch record set; locate the goal by slug (`goal-not-found`; `ambiguous-slug` if duplicated); if `parent` present, `validateDecompositionOp` enforces adoption rules; read the element's current json, **backfill `capturedOn: resolveCaptureDate(record)` into the section when absent** (a re-sign resets the event's `created_at`; without the backfill the first update of a legacy goal would silently move its capture date to today — this pins the true date permanently), shallow-merge the provided fields into `tapestryOwnerGoal` (all other sections/fields pass through verbatim), `regenerateJson(uuid, merged)`. Sharpening (overwriting an existing deliverable/boundary with new words) is allowed — the story's "or later sharpens." Discriminated results: `{success:true, result:'updated', fields:[...], goal:{uuid, slug}}` / loud named refusals, nothing written.
   **Serialization (both primitives):** the two handlers run their read-validate-write bodies through a module-level promise-queue mutex (the module is a process singleton). Without it, two concurrent in-contract adoptions (A under B ∥ B under A) both validate against pre-write state and commit a 2-cycle — which, with re-parenting out of scope, would be unrepairable in-contract. The mutex closes the in-contract race; out-of-contract raw writes remain the resolver's and taxonomy's job.
8. **Option C lands — scoped deliberately.** `handleReconcilePrimaryProperty`'s post-gate body is extracted into a module-internal `reconcilePrimaryPropertyForConcept(conceptName)` returning its discriminated result; the route handler wraps it (gate + res; behavior byte-equivalent — story-2 S4's mechanism pins are re-aimed onto the extracted function, see Implementation notes); `handleSaveSchema` calls it after `regenerateJson(schemaUuid, …)` and reports the outcome in its response as `primaryProperty: <result>`. The extracted function gains one new non-alarming result — `'not-applicable'` — for concepts whose schema does not follow the single-concept-object convention or that lack a primary-property node (the current loud refusals stay for the *standalone endpoint's* direct calls, where the caller named a concept expecting reconciliation; the fold maps those conditions to `not-applicable` so `save-schema` on unconventional concepts is not noise). **Disclosed reach:** firmware install pass 2 calls `save-schema` per firmware concept, so installs now also heal genuinely drifted primary-property records *toward the firmware schema being saved* — convergent by construction; `comparePropertyRecord` ignores cosmetic richness, so consistent-but-richer firmware pp nodes are never rewritten (no-write on `already-consistent`); a drifted *and* rich pp node is rewritten in stripped `{type}` form, and the next full install re-derives it from firmware regardless (documented note). Install error behavior is unchanged (it reads only `success`). This erases the read-compare-write race for the save-schema flow (row 85b) and the paired-call burden; the standalone endpoint remains for repair/bootstrap. `save-schema`'s gating is unchanged (0002's explicit non-retrofit; middleware already 401s/403s remote callers).
9. **Hygiene taxonomy, grown deliberately** (0002 Consequences; row 85): new pure classifier `classifyDecomposition({concept, records})` emitting `dangling-parent-reference` (a goal's `parent` slug resolves to no goal; detail names goal and slug), `decomposition-cycle` (a parent chain revisits a goal; detail names the cycle members; self-parenting is the length-1 case), and `duplicate-slug` (two or more goal records share a slug; detail names the slug and the shadowed uuids — the out-of-contract collision detector the write-path refusal cannot cover). Wired for the goal concept only in `checkConcept` (records parsed via the shared `parseGoalRow` — one classification truth). Row-85c taken: unreadable *schema* input to `comparePropertyRecord` now reports kind **`schema-unreadable`** (same detail sentence); the unreadable *property-section* path stays `property-record-drift` (it genuinely is the record's defect; story-2 U7(e) pins that path and needs **no** amendment). Row-85d resolved by a code comment at the ignore site making the non-Superset-membership ignore explicit and deliberate (no new kind — no story-3 structure can produce such an edge). Row-85a resolved via this ADR's **Amends** header. The taxonomy doc block grows from five to **nine** kinds.
10. **UI — tree in `Goals.jsx`:** group by `parentUuid`, render depth-first; parent rows get the disclosure glyph `▸` (rotated 90° when open, default expanded); leaf rows get the wireframe's `·` placeholder; indent 20px per depth (12px under 768px) via a component-level CSS custom property on the row (no new `:root` tokens); the standing word renders as today (now including `viable`); a `captured` **leaf** row carries the design guide's verbatim hint line *"needs a deliverable and boundary before it can be proposed"* (muted, under the name). **Hit areas:** the disclosure control occupies the full row *height* at the row's left edge (≥44px target — the design guide's actual rule); the row's remaining area (and Enter) navigates to the detail; the disclosure stops propagation. Rows whose record has no `slug` render **unlinked** (no navigation target exists — see d11). Cold-start, privacy line, loading, error states and the new-row highlight are unchanged. **Token constraint for the Implementer:** story-1 S5b scans the whole of `Goals.jsx` for `toggle|checkbox|switch` (case-insensitive) — name the disclosure identifiers `disclose`/`expand`-family; do not amend S5b.
11. **UI — minimal Goal detail:** new flat leaf route `/tapestry/goals/:slug` (`crumb: 'Detail'`, `TrustedListDetail` structural precedent, `.brain-*` styling, the same gate branches as Goals.jsx). No new API: the page uses `useBrainGoals` and selects the record by `slug` (small corpus; story 4's one-spine page is the natural moment for a per-goal endpoint; if duplicates exist the page shows the resolver's winning record — same truth as the tree). Contents top-down: a "← Goals" back link (wireframe §2; also satisfies the 768–1024px responsive rule "detail replaces tree with a back link"); `<h1>` goal name; metadata line — standing word · *part of "{parent name}"* (when `parentUuid` resolves; the parent's display name, linked to its own detail) · captured {captureDate} · {origin, when non-null}; the statement as body text; then the two labelled fields exactly as the wireframe: **Done means:** {deliverable} / **Stays inside:** {boundary} — each line rendered only when the field exists; a `captured` leaf missing either shows the verbatim hint line instead (leaves only — a parent goal shows no hint). Unknown slug → plain-language not-found line with a link back to Goals (register-conformant; exact sentence is the Implementer's, reviewer-enforced). No edit affordances anywhere.
12. **Conversational contract addendum** (0001 d1 grows; story 5 makes it agent-discoverable): add a child — `POST /api/normalize/create-child-goal` (d6 body); state or sharpen intent / adopt — `POST /api/normalize/update-goal-intent` (d7 body); the agent reads slugs from `GET /api/brain/goals` and utters the one-sentence confirmations itself (register-conformant; API responses are never owner-facing).
13. **Schema extension bootstrap (operational, one-time, journaled):** deploy the code (so the fold is live), then one `save-schema` call with the complete schema — existing five properties plus optional `deliverable`, `boundary`, `parent` (type string, plain-language descriptions; `required` and `x-tapestry.unique` unchanged) — which auto-reconciles the primary property in the same call; read back `GET /api/brain/hygiene` green as the assertion. **The test suite never runs `save-schema` itself** (re-signing the schema node every run is churn): H rows *assert* the live schema declares the three new optional fields and hygiene is green, skipping with the suite's stack-precondition pattern where the stack is absent. Fresh-instance bootstrap order becomes: `create-concept` → `save-schema` (complete, auto-reconciling) → elements.

## Consequences

- **Enables:** session-sized viable pieces with the standing word story 6's proposer selects on; a validated write contract the conversational agent can trust (refusals are system behavior); slug-based decomposition that survives export/restore (story 8) and second-operator bootstrap, with its uniqueness premise enforced at the only path that can enforce it; schema extensions that no longer strand the primary property (this story's own extension is the first beneficiary); a tree the UI renders mechanically from one server-side resolution truth; goals created through the new contract can no longer silently overwrite each other (a live hazard until now).
- **Constrains:** the tree remains record-based — any future edge materialization must supersede this ADR *and* go through the relationship-primitives whitelist-extension path; the brain module stays read-only (writes continue to accrete in normalize until a dedicated brain-write ADR argues otherwise — story 5's work records remain the likely first case); child names are unique concept-wide (create-element's dedup adopted, now strengthened to slug/d-tag); adoption is one-shot (parentless goals only); `save-schema` now has a second effect on every caller including firmware install (scoped and disclosed in d8).
- **Debt / follow-ups:** (a) `save-element-json`/`set-json-tag` remain ungated raw-write escape hatches that can bypass decomposition validation — pre-existing flagged debt, now with read-time tolerance (`slugShadowed`/`parentUnresolved`/cycle-break) and three detection kinds compensating; the security follow-up should weigh gating them. (b) ~30 lines of concept-lookup Cypher duplicated between `create-element` and `create-child-goal` — accepted over refactoring the composite module's main path. (c) The standalone reconcile endpoint retains its unlocked read-compare-write (row 85b residual — bounded: idempotent, operator-traffic, checked); the save-schema flow and the two new primitives are serialized. (d) An out-of-contract cycle, if one is ever written raw, has no in-contract repair (re-parenting is out of scope) — the resolver renders it tolerantly and hygiene names it; repair is a raw operational act or a future story. (e) The story-1 capture contract (`create-element` direct) still carries the name/d-tag collision hazard for *top-level* captures — out of this story's scope; recorded for the security/hardening follow-up and mitigated by `duplicate-slug` detection.
- **Firmware reinstall required?** **No.** Concepts are runtime-created; the schema change is a live `save-schema` call; installer untouched (operator decision 2026-07-18) — d8 changes what the *existing* install calls do only via `save-schema`'s response body, which install ignores beyond `success`.
