**Status:** Accepted
**Date:** 2026-07-24
**Story:** `engineering-team/stories/second-brain/8-the-brain-survives.md`
**Builds on:** second-brain ADRs 0001–0007 — this story is a pure *consumer* of the five families those ADRs built: it reuses the brain module's EXPLICIT∪IMPLICIT union read (0001 d3), the runtime-created-concept ensure idiom (0004→0007: `ensureResourceConcept`/`ensureWorkRecordConcept`/`ensureProposalConcept`/`ensureSignalConcept`), the name-derived goal mint with its loud `name-collides` guard (0003 d2/d6 — `createChildGoal`, `src/api/normalize/index.js:2227-2242`), the nonce-d-tag record mint (0005→0007: `mintProposalElement:3089`, `mintSignalElement:4710`), the gated/validated/serialized/local-only write pattern, and record-based slug linkage (0003 d2, 0004 d2, 0005 d4, 0006 d4, 0007 d3) — which is precisely what makes a verbatim-content restore possible with zero edge reconstruction. **This is the fifth runtime-created append-only concept** (External Resource → Work Record → Proposal → Priority Signal → Restore Drill) and the second born-final one (signals precedent).

## Context

The story (`8-the-brain-survives`, gate-approved 2026-07-24). Acceptance criteria, quoted to confirm:

- **AC1** — export produces a **dated, local artifact** carrying all five families (goals **with decomposition positions**, resources, signals, proposals **with decisions**, work records); owner-authored content, **not a whole-database backup**.
- **AC2** — a restore drill against a **scratch target** reproduces the content as **equivalent content**; the live brain is untouched except **(c)** the drill's **journal entry** — dated, durable, append-only, discoverable from the brain itself; the drill has actually run once; completion confirms with the pinned *"Restore drill complete — your brain matches the export."*
- **AC3** — **no egress** (§7.4): export touches/publishes nothing outward; restore writes are local to their target.
- **AC4** — export twice with no changes → **equivalent content** (the artifact's own taken-on dating may differ; nothing about the content may).
- **AC5** — copy discipline (pinned strings verbatim; new strings gate-ratified); **no reference-instance identities** in artifact or restore path; a truly empty scratch target self-provisions; stories 1–7 suites stay green.

Facts established at architecture recon (live instance + source, 2026-07-24; TA `11f23fe4…93767` runtime-resolved; concept-graph orientation before source):

- **All five families have live read paths AND parsers** — `readResolvedGoals`/`readResourceRecords`/`readWorkRecords`/`readProposals`/`readSignals` (`src/api/brain/index.js:90-169`), each the same EXPLICIT∪IMPLICIT union; parsers in `src/lib/brain/{goals,resources,work-records,proposals,signals}.js` whitelist rows into records and **return null on non-members** (the membership test the export reuses).
- **All cross-record linkage is slug/locator fields INSIDE the json sections**: goal `parent` (slug), resource `goal` (slug), work-record `goal` + `produced` (locators), proposal `goal` + decision `proposalId` (→ the proposed fact's **slug** — `openProposals`, `src/lib/brain/proposals.js:106-115`), signal `prefers`/`over` (slugs). **A restore that writes sections verbatim preserves every link byte-for-byte** — no edge reconstruction, no id rewriting.
- **The clobber vector is already named in source**: goal d-tags derive from the name, so a colliding mint would make `importEventDirect` **MERGE over the existing goal — a silent overwrite**; `createChildGoal` refuses loudly (`name-collides`) checking name, slug, AND derived d-tag (`normalize/index.js:2227-2242`). Restore inherits exactly this guard, generalized upfront.
- **Correction to the handoff's premise: the goal concept is NOT firmware-seeded.** ADR 0001 is explicit: `tapestry-owner-goal` was runtime-created via `create-concept` (2026-07-18); `grep -rl tapestry-owner-goal firmware/` is empty; *"other deployments do not have the concept at all until it is bootstrapped there."* There is **no `ensureGoalConcept` anywhere** — story 1's bootstrap was conversational. A truly fresh target therefore lacks **all five** concepts, and restore must ensure all five. The live goal schema (read from the graph this session): section `tapestryOwnerGoal`, required `[name, slug, description]`, optional `origin/capturedOn/deliverable/boundary/parent`, `x-tapestry.unique: ['name','slug']`.
- **Record mints override derived name/slug when the section carries them**: `mintSignalElement` builds `{ name: …, slug, ...section }` (`:4714`) — the spread-last idiom means a verbatim-section mint is structurally natural.
- **The brain import surface is NINE, septuple-pinned** — the identical allowlist in seven suites (`capture:333`, `structures:454`, `break:540`, `attach:560`, `sessions-read:573`, `the-proposal-loop:580`, `teach-it-what-matters:563`). A tenth require amends **all seven in the same diff** (eighth occurrence of the lesson).
- **Auth classes**: brain GETs reach handlers and gate in-handler (`isOwner(req) || req.localTrusted` → 403); POSTs default-deny remote at middleware (401) unless in `PUBLIC_MUTATIONS` (`src/middleware/auth.js:454` — only neo4j/query + strfry/publish; **untouched**).
- **UI**: `ui/src/pages/brain/Goals.jsx` renders title → tree → `brain-privacy-line` footer (`:190`). Download precedent exists (`ui/src/pages/io/ExportPage.jsx` — server export + `<a download>`). The design guide's screen inventory has **no export surface** (the story's Open Q1); the style guide pins the **button label** `"Export brain."` and the drill confirmation.
- **Local container reality**: one `tapestry` container (image `tapestry-tapestry`) runs the control panel + Neo4j + strfry + strfry-router under supervisord; first boot creates a **fresh TA identity** (`docker/entrypoint.sh:215-218`); firmware install is a **manual deployment step**, not a boot step. A second ephemeral container from the same image with fresh anonymous volumes and **no published ports** is a genuinely fresh instance — its own TA, its own empty graph — reachable only via `docker exec` loopback (the `localTrusted` class).
- **Derived state is not content**: standing, freshness, open-ness, and decomposition annotations (`parentUuid`/`hasChildren`/…) are all derived at read (0001 d4, 0004 d13, 0006 d10, 0003 d4). The export carries **stored content only**; a restored instance re-derives everything (event-tagging 0009 discipline extends to the artifact).

## Options considered

### Option A — verbatim-section artifact via a read-only brain GET; collision-refusing verbatim re-mint restore in normalize; a fifth runtime concept journaling the drill; the drill scripted against an ephemeral fresh container

The export artifact is `{format, version, takenOn, content: {goals, resources, workRecords, proposals, signals}}` where each family entry is `{name, section}` — the element's event **name** and its **raw json section verbatim** (membership decided by the existing parsers; canonical sort for determinism). Assembled read-only in the brain module, downloaded from a quiet Goals-view footer affordance. Restore is one gated normalize producer that validates shape, **pre-checks every collision across all five families, refuses wholesale before any write**, then ensures concepts lazily (all five — including the new `ensureGoalConcept`) and re-mints each section **verbatim** under the target's own TA (goals: name-derived d-tags, the capture idiom; records: nonce d-tags, the mint idiom). The drill is a script that boots a fresh scratch container, restores into it, re-exports it, compares with one pure `contentEquivalent`, journals the result into the **live** brain under the new `tapestry-restore-drill` concept, and tears the scratch down.

- **Pros:** raw sections make round-trip fidelity structural — no field mapping, no silent loss of out-of-contract fields (the cardinal sin for a protection artifact); slug linkage survives byte-for-byte because it *is* section content; the artifact contains **zero identities** (no pubkeys, no uuids, no handles) so §5.9 holds by construction; ONE equivalence definition serves export-idempotence (AC4) and restore-reproduction (AC2) mechanically; every write idiom is a byte-familiar repetition (fifth ensure, third born-final concept, the established collision guard generalized); derived state stays derived (0009); the scratch container's fresh TA makes the portability proof real, not simulated.
- **Cons:** the tenth brain require trips the septuple pin (planned re-pin ×7 — the known cost); restore is not transactional (a mid-restore crash leaves a partial scratch — recovery is documented as tear-down-and-redrill, acceptable for a scratch-only act); raw fidelity means a hand-edited artifact restores whatever it says (bounded: owner-gated, shape-validated, and the read paths whitelist at render); the drill script depends on docker + the local image (environmental — the suite never depends on it).

### Option B — parsed-projection artifact and/or a server-side artifact store

Export the *parsed record shapes* (statement instead of description, derived fields included) and/or have the server write dated artifact files to a managed directory with a retention scheme.

- **Cons (dispositive):** a projection artifact must be un-mapped at restore (field renames both ways — a standing translation layer to maintain) and **silently drops any field the parser doesn't know** — data loss exactly where the product promises survival; including derived fields (standing/freshness) embalms view-state the target must recompute anyway (0009 violation). A server-side store adds filesystem management, retention policy, and path questions the story explicitly leaves with the owner ("where the owner carries the artifact afterwards is their business"), and weakens §7.4's story ("lands locally" is most honest as a browser download the owner placed). **Rejected.**

### Option C — raw-event replay restore

Export the signed kind-39999 events themselves; restore replays them into the target's strfry/Neo4j byte-true.

- **Cons (dispositive):** the events are signed by the **reference instance's TA** — replaying them on a second operator's instance either fails signature-vs-authority checks or plants a foreign pubkey as the author of the target's brain content, and every header handle (`39998:<TA>:…`) embeds the wrong TA — the exact reference-instance bake-in §5.9 forbids. Re-signing others' events is impossible without their key; re-signing under the target's key is just Option A with extra steps and stored identities in the artifact. AC4's own wording ("equivalent content", not byte-identical) anticipates re-mint. **Rejected.**

## Decision

We chose **Option A.** Sub-decisions, each binding:

1. **Artifact format (identity-free, versioned, dated).** `{"format": "tapestry-brain-export", "version": 1, "takenOn": "<ISO date>", "content": {"goals": [], "resources": [], "workRecords": [], "proposals": [], "signals": []}}`. Each family entry is `{"name": <element event name>, "section": <the family's json section, verbatim>}`. Membership per family = the existing parser accepts the row (`parseGoalRow`/`parseResourceRow`/`parseWorkRecordRow`/`parseProposalRow`/`parseSignalRow` ≠ null); the exported `section` is the **raw stored object**, not the parsed projection. Elements that fail parsing are **not** exported (they are not brain content; hygiene's territory — documented boundary). **No uuids, no createdAt, no pubkeys, no handles anywhere in the artifact** (S-scannable; §5.9 structural). Families sort canonically: by `section.slug`, tie-broken by the JSON-stringified section — a stable total order, so serialization is deterministic. `takenOn` = ISO date (the convention of `capturedOn`/`judgedOn`); filename `brain-export-<takenOn>.json`.
2. **One equivalence definition — `contentEquivalent(a, b)`** (the story's Open Q4, ratified here): two artifacts are equivalent iff their canonically-sorted `content` values are deep-equal. This single definition serves **AC4** (export twice, unchanged brain → deep-equal content; same-day double export is byte-identical including `takenOn`) and **AC2** (restore reproduces: re-export the target after restore → `contentEquivalent(artifact, targetExport)` — true because restore mints name + section verbatim). The envelope's `takenOn` is outside the comparison; `uuid`/`createdAt` never enter the artifact at all.
3. **Export read surface: `GET /api/brain/export`** — the brain module's sixth route, in-handler gate (`isOwner || localTrusted` → 403, the sibling pattern). Assembles via a new raw-row helper (`readFamilyRows(taPubkey, conceptSlug)` — the same EXPLICIT∪IMPLICIT union returning rows; the five existing read functions stay **byte-unchanged**) mapped through the pure export core. Response headers set `Content-Disposition: attachment; filename="brain-export-<takenOn>.json"`. Reads never provision or mutate (0001 discipline); an empty/absent family exports `[]` — an empty brain exports a valid, restorable artifact.
4. **New pure core `src/lib/brain/export.js`** (zero-require CJS, the sibling precedent) — the artifact format's single owner: `familyEntries(rows, sectionKey, parser)` (parser-validated membership → `{name, section}` with raw section extraction), `canonicalContent(content)` (sort), `assembleExport(familiesByKey, takenOn)`, `contentEquivalent(a, b)`, `validateArtifact(artifact)` (shape: format/version/content keys/entries `{name: non-empty string, section: plain object}`/`section.slug` non-empty string — returns `{ok}` or `{error}` in plain words). **This is the brain module's TENTH require** — the septuple pin re-pins to ten across **all seven sibling suites in the same diff** (d13).
5. **New pure core `src/lib/brain/restore.js`** (zero-require CJS): `planRestore(artifact, existing)` where `existing` is the target's current five families (parsed records). Computes, before any write: **goal collisions** — any artifact goal whose `name`, `slug`, or name-derived d-tag part matches an existing goal (the `createChildGoal` triple, generalized); **record collisions** — any artifact record whose `section.slug` already exists in that family on the target (keeps `openProposals`' slug-keyed decision matching unambiguous). Returns `{refusal: 'goal-collides'|'record-collides', collisions: [...]}` (all of them, named) or the ordered mint plan: goals → resources → workRecords → proposals → signals. **All checks precede all writes; a refusal writes nothing.** Restore does NOT require an empty target (the drill's target is fresh anyway; the H-suite restores sentinel artifacts beside live content) — emptiness is not the guard, collision is: **a real restore-of-the-live-export attempted against the live brain refuses on every goal** — the protection is structural.
6. **Restore producer: `POST /api/normalize/restore-brain`** `{artifact}` — gate-first (`isOwner || localTrusted` → 403; remote 401 via default-deny middleware — `PUBLIC_MUTATIONS` untouched); shape problems 400 (via `validateArtifact`); domain refusals HTTP-200 `{success:false, refusal, error}` (the epic contract). The entire restore runs inside **one** `serializeGoalWrite` task (mutex not renamed): fetch existing five families → `planRestore` → refuse or mint the plan in order. Result `{success: true, result: 'restored', restored: {goals: n, resources: n, workRecords: n, proposals: n, signals: n}}` (API surface, not owner-facing copy). **Not transactional** (append-only world, no rollback): a mid-restore crash leaves a partial target; re-running refuses on collisions; recovery = discard the scratch and re-drill (documented consequence, acceptable for a scratch-only act).
7. **Verbatim re-mint under the target's identity.** Goals: `mintRestoredGoal` — d-tag `dtag.childDTag(section.name ∥ name, headerUuid)` (the capture idiom: name-derived, deterministic per instance), tags `[d, name(verbatim), z(target header), json {tapestryOwnerGoal: section(verbatim)}]`, node `slug` property = `section.slug` (verbatim); **`capturedOn` is NOT restamped** — the artifact's dates are the content. Records: `mintRestoredElement` — nonce d-tag (`randomDTag()`, the mint idiom: no MERGE-over possible), name + section verbatim, node slug = `section.slug`. Both: `signAndFinalize` (target's TA) → `publishToStrfry` → `importEventDirect` → `SET :ListItem` → `MERGE superset→elem` — the established local-only write spine; **nothing on any restore path calls `regenerateJson` or re-signs an existing event.**
8. **`ensureGoalConcept()` — new, closing ADR 0001's bootstrap gap.** Structural copy of `ensureSignalConcept` (`:4690-4703`): resolve (`resolveGoalConcept`, exists at `:2168`) → return if present (**no-op on the reference instance**); else `create-concept` (name `tapestry owner goal`, plain description per PRD §6) + `save-schema` with `GOAL_SCHEMA` — section `tapestryOwnerGoal`, required `[name, slug, description]`, properties `name/slug/description/origin/capturedOn/deliverable/boundary/parent`, `x-tapestry.unique: ['name','slug']` (mirroring the live schema's fields; the SIGNAL_SCHEMA idiom — functional equivalence, not byte-decoration) → re-resolve, loud throw on failure. Restore ensures **lazily per family, only when that family has entries to mint** (the self-provision-on-first-content semantic): all five ensures available to it (`ensureGoalConcept` + the four existing). Never firmware-seeded (§7.8).
9. **The drill journal (the story's Open Q3, ratified here): a FIFTH runtime-created append-only concept.** Name **`tapestry restore drill`** → slug `tapestry-restore-drill` → handle `39998:<TA>:tapestry-restore-drill` (TA runtime-resolved). Born final (the signal precedent — no lifecycle). Single wrapper `restoreDrill`; fields (plain-language descriptions): `name`, `slug`, `description`, `exportTakenOn` (the drilled artifact's date), `drilledOn` (server-stamped today), `outcome` (`matched` | `did-not-match` — the two canonical words), `target` (the scratch environment in plain words), `performedBy` (`'owner'` — the d7 precedent, instance-relative); `required`: all of them; `reason`-style optionals: none. Producer **`POST /api/normalize/record-restore-drill`** `{exportTakenOn, outcome, target?}` — gate-first, 400 on missing/malformed fields or an outcome outside the two words, `target` defaults `'a fresh scratch instance'`, one `serializeGoalWrite` task, `ensureRestoreDrillConcept()` + `mintRestoreDrillElement` (nonce d-tag). **Both outcomes are journaled** (the queue says "the drill's *result* is journaled" — honesty includes a mismatch). Discoverable from the brain by search-plus-connections (the §5.9 standard; the concept pages remain the browse surface — design guide principle 1); **no new brain read route** (the d10-precedent: no route without a consumer) and **no spine projection** (a drill serves no goal). *(Named alternative — a work record: rejected; work records require a served goal, no natural goal exists, and planting one violates §5.9/§7.3.)* **Drill records are NOT exported** — AC1's five families are the contract; safeguard history is instance-local (documented).
10. **The scratch target (the story's Open Q5, ratified here) and the drill script.** Scratch = **an ephemeral second container from the same `tapestry-tapestry` image, fresh anonymous volumes, NO published ports** — a genuinely fresh instance (its own TA at first boot — the §5.9 proof is real, not simulated; unreachable from off-machine — egress hygiene by construction), reachable only via `docker exec` loopback (`localTrusted`). **`scripts/brain-drill.sh`** (engineering tooling — the design guide binds UI, not scripts): (a) preflight — live stack answering, image present; (b) export the live brain via loopback → artifact file; (c) boot scratch (`docker run --rm`, fresh volumes, no `-p`), wait health (bounded until-loop); (d) run the standard deployment bring-up inside scratch — firmware install (`POST /api/firmware/install`, AGENTS.md §6 — the second-operator baseline), then `supervisorctl stop strfry-router` in scratch (no sync churn); (e) `restore-brain` the artifact via scratch loopback; (f) re-export scratch, compare via `node -e` + `contentEquivalent`; (g) journal the outcome into the **LIVE** brain (`record-restore-drill` via live loopback); (h) on match print the pinned *"Restore drill complete — your brain matches the export."* (on mismatch: a plain error naming the first difference, still journaled `did-not-match`, non-zero exit); (i) tear down (`docker rm -f`; `--rm` + anonymous volumes self-clean). The drill is an **operator act run once at implementation** (the §10 metric row; AC2 requires it to have actually happened) — **the test suite never boots the scratch** (H rows cover export/restore mechanics against the live local instance with sentinel fixtures; the drill is environmental by design).
11. **The export affordance (the story's Open Q1, proposed for ratification).** The Goals view's **footer**, beside the privacy line (`Goals.jsx:190`) — a quiet outline button labeled **`Export brain.`** (pinned verbatim). Rationale: the privacy line and the export affordance are the same posture — *your brain is yours, on this machine* — and the Goals view is the "what do I have?" surface; footer placement leaves the tree the screen's one primary concern (design principle 1). Present in the empty state too (an empty brain exports a valid artifact). Interaction: click → fetch `GET /api/brain/export` → client-side blob download named per d1 → the one-sentence confirmation appears beside the button; while in-flight the button disables (no spinner theater, no progress numbers). *(Named alternative — a header-row button beside the view title: rejected; competes with the title, and the guide's screens carry no header chrome.)*
12. **Owner-facing wording (the story's Open Q2, proposed for ratification — the d16/d5 precedent; verbatim-or-block at review; guide back-fill at book-close):**
    - Button label: **`Export brain.`** (style guide line 24, already pinned).
    - Export confirmation (NEW): **`Exported — saved to this machine.`** — register family of *"Skipped — noted."*; echoes the privacy line's posture; no jargon, no numerals, no exclamation. *(Named alternatives: "Exported — the file is with your downloads." — rejected-by-default, "downloads" is browser furniture; "Brain exported." — rejected-by-default, drops the where.)*
    - Export failure (NEW): **`Couldn't export — nothing was saved. Try again.`** — the style guide's error pattern (what went wrong, in whose terms, what to do); the retry affordance is the button itself.
    - Drill completion: **`Restore drill complete — your brain matches the export.`** (style guide line 27, already pinned) — uttered by the drill script on match (and by the conversational lane when relaying).
    - Drill journal element `description` (stored plain-language baseline): `restore drill: the export taken <exportTakenOn> was restored to <target> and <matched the export | did not match the export>.`
    - All strings pass the banned-jargon scan; no numerals in any owner-facing string this story adds.
13. **Test-surface amendments (planned here — the complete set, eighth occurrence of the lesson).** The brain import allowlist re-pins from NINE to **TEN** (`+ /lib\/brain\/export$/`) across **all seven sibling suites in the same diff** (`capture:333`, `structures:454`, `break:540`, `attach:560`, `sessions-read:573`, `the-proposal-loop:580`, `teach-it-what-matters:563`). `registerBrainRoutes` gains exactly ONE route (`/api/brain/export`) — sibling suites pinning the route list (if any pin exact) amend accordingly; `restore.js` is required by normalize only (no brain-pin impact).

## Consequences

- **Enables:** the trust floor — a dated, identity-free, deterministic artifact of everything the owner authored, provably restorable (drilled once, journaled in the brain itself); the §10 metric row ("1 journaled export/restore drill") becomes countable by inspection; the §5.9 portability seed exists in earnest (a second operator restores the artifact on an instance whose TA differs — proven by the drill's fresh-TA scratch); the interim reinstall-clobber protection the queue assigns this story; a general `restore-brain` capability any future migration/merge work builds on (behind its own future stories).
- **Constrains:** restore semantics are **collision-refuse, never merge** (merge is a later product question — story Out of scope); restore is not transactional (partial-restore recovery = discard the scratch); the artifact carries stored content only — derived state (standing, freshness, open-ness, tree annotations) re-derives on the target, so a restored brain is *semantically* identical, not byte-identical (AC4's "equivalent content", by design); export reads all five families on every call (O(N), the codebase's standard derive-at-read cost; the Phase-4 index deferral unchanged); drill records accumulate append-only and are instance-local (not exported).
- **Debt / follow-ups:** (a) elements that fail their family parser are silently excluded from export — a hygiene-classifier extension ("unexportable rows") is a natural later addition; (b) the drill script is environmental (docker + local image) and never suite-run — CI proves mechanics via H rows, the operator proves the product act; (c) `tapestry-restore-drill` is not hygiene-covered (precedent-consistent); (d) the raw `save-element-json` hatches can still write junk that export faithfully carries — pre-existing flagged debt, compensated by parser-membership at export and read-tolerance everywhere; (e) the ratified d12 strings + the export affordance's placement need style/design-guide back-fill at book-close (joining the ADR 0006 d16 + 0007 d5 bundle).
- **Firmware reinstall required? No.**
