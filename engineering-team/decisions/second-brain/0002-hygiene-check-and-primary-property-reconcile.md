# ADR 0002: Read-only hygiene surface on the brain seam; targeted primary-property reconcile primitive in normalize

**Status:** Accepted
**Amended by:** ADR 0003 (d4 schema-object resolution — sole top-level *properties* key, not *required* key; Consequences (a) paired-reconcile requirement dissolved for the save-schema path by the 0003 d8 fold)
**Date:** 2026-07-23
**Story:** `engineering-team/stories/second-brain/2-structures-the-brain-can-trust.md`

## Context

The story: a repeatable check validates the two work-item concepts' structures against class discipline (AC 1), adjudicates the queue's flagged membership edges as sound and retains them (AC 2), reconciles the one verified live defect — the primary-property record lagging the extended schema (AC 3) — reports known-kind recurrence specifically (AC 4), loses no goal (AC 5), and is sound on any instance with no hardcoded identity (AC 6).

Facts established at planning recon (live, directed Cypher, 2026-07-23) and from source:

- **The live defect is node content, not edges.** `39999:<TA>:tapestry-owner-goal-primary-property` carries `property: {key, title, type, required: [name, slug, description], properties: {name, slug, description}}` while the schema element's `jsonSchema.properties.tapestryOwnerGoal` now also declares optional `origin` and `capturedOn` (story 1's `save-schema`). `handleSaveSchema` (`src/api/normalize/index.js:1899-1973`) regenerates only the schema node — the drift is by construction and **will recur at story 3**, which extends the schema again (deliverable/boundary/parent/category).
- **All flagged edges are sound.** Directed inventory of both headers shows identical, correct wiring: outgoing `HAS_TAG`×6 + exactly one `IS_THE_CONCEPT_FOR` → `:Superset`; incoming `HAS_ELEMENT` from `concept-header-superset` (universal — all 44 headers) plus the six machinery `IS_THE_*_FOR` edges. No outgoing `HAS_ELEMENT` exists on either header. The goal superset's two incoming `HAS_ELEMENT` edges (from `set-superset`, `superset-superset`) are legitimate class membership. Each of the three goal elements has both its membership edge and a matching z-tag.
- **The reuse surface is ready.** `src/lib/brain/goals.js` is dependency-free CJS whose docblock names story 2's checker as its second consumer; `parseGoalRow` classifies rows tolerantly. `src/api/brain/index.js` establishes the read-route pattern: in-handler `isOwner(req) || req.localTrusted` gate, runtime TA via `getOwnerAssistantPubkey()`, parameterized directed Cypher, S-pinned import surface, strfry-free.
- **The write machinery exists.** `regenerateJson(uuid, jsonValue)` (`normalize/index.js:56-85`) rebuilds an event's tags with a replaced json tag, re-signs with the runtime TA key, publishes to **local** strfry, re-imports to Neo4j — the exact path `save-schema` rides. The create-concept generator (`:1394-1417`) defines the primary-property `property` section convention: per-property definitions stripped to `{type}`, `required` mirrored from the schema.
- **Recurrence context:** firmware install pass 1d re-derives membership edges from surviving z-tags (`src/firmware/install.js:594-639`) — cleanup permanence can never be assumed; the installer is untouched (operator decision 2026-07-18). The goal and project concepts are runtime-created, so reinstall does not touch their machinery nodes.
- Binding prior ADRs: second-brain 0001 (brain seam is read-only; core reuse; empty brain is a state; platform gate template), relationship-primitives 0001+0002 (`relationships.js`/`probe.js` byte-pinned, untouched; whitelist never extended here — this story mutates node *content*, not edges), event-tagging 0002 (never `publishEverywhere` — `regenerateJson` is local-only), event-tagging 0009 (derive at read time; no stored verdict flags), security-auth-exposure 0001+0002 (explicit in-handler gates on new mutations), test-hermeticity 0001 (U/S/H classes), ADR 0015 (legacy files untouched).

## Options considered

### Option A — Read-only hygiene on the brain seam (`GET /api/brain/hygiene` over a pure core) + a targeted, idempotent reconcile primitive in normalize (`POST /api/normalize/reconcile-primary-property`)

The check ships as `src/lib/brain/hygiene.js` (pure, dependency-free except `./goals`) fed by directed parameterized Cypher from a new route in `src/api/brain/index.js`. The cleanup ships as one new normalize endpoint that mechanically derives the primary-property `property` section from the concept's current schema and calls `regenerateJson` — discriminated results (`reconciled` / `already-consistent`), loud named precondition failures, explicit in-handler gate.

- **Pros:** honors 0001's separation exactly — brain stays read-only and strfry-free (its S-pinned import surface grows by one pure-core require); the write rides normalize's existing signing/publish/import machinery next to `save-schema`, whose lookup idiom it mirrors; the defect taxonomy lives in a pure core so every AC-4 kind is U-testable with synthetic rows — no live-graph vandalism needed to test defect reporting; the reconcile is reusable at story 3's schema extension and at every second-operator bootstrap (AC 6), where the same drift is produced by construction; idempotency makes it journal-safe and H-testable.
- **Cons:** two new surfaces to maintain; the reconcile endpoint is generic across concepts (name-parameterized like `save-schema`), which is slightly more than the story's minimum of "fix the goal concept."

### Option B — Check only; cleanup as a journaled operational `set-json-tag` call

`POST /api/normalize/set-json-tag` (`:3248-3297`) can already replace the primary-property node's json; the fix becomes a hand-built payload journaled at implementation (story 1's `save-schema` precedent), and no write code ships.

- **Pros:** zero new mutation surface.
- **Cons:** the payload is hand-derived — nothing guarantees it agrees with the schema (`set-json-tag` validates nothing), and the drift recurs at story 3, at every future schema extension, and on every fresh deployment's bootstrap — each time demanding another hand-built payload while the check sits red. AC 3 becomes an assertion about an operator's one-time action rather than shipped, testable behavior. Rejected.

### Option C — Root-cause: `handleSaveSchema` regenerates the primary-property node in the same call

- **Pros:** kills the drift class at the write path for every concept, permanently.
- **Cons:** a behavior change on a shared endpoint that touches all 44 concepts, including firmware-seeded ones where reinstall would clobber the regenerated node back (the separate firmware-protection epic's territory); the check must exist regardless (PRD §5.7 demands detection); the story scopes cleanup to the goal concept's record. Deferred, not rejected — the right moment is story 3, which touches `save-schema` next and can fold reconciliation into that ADR with this story's check already standing guard. Recorded in Consequences.

## Decision

We chose **Option A**.

Sub-decisions, each binding:

1. **Check surface:** `GET /api/brain/hygiene` in `src/api/brain/index.js`, in-handler gate `if (!isOwner(req) && !req.localTrusted) return 403` (0001 decision 3's template), TA at request time. Covers exactly two concepts by slug constant: `tapestry-owner-goal`, `project-for-the-engineering-team` (handles constructed at runtime; slugs are legitimate constants per 0001's `GOAL_CONCEPT_SLUG` precedent). Response: `{ success: true, sound: <bool>, problems: [...], checked: [...] }`. An absent concept contributes `{ concept, present: false }` to `checked` and **no problem** — nothing-to-check is a state, not a defect (AC 6, PRD §5.9). Read-only: no mutation, no strfry, no auto-provisioning.
2. **Pure core** `src/lib/brain/hygiene.js` (CJS; requires only `./goals`). The defect taxonomy — the AC 4 "known kinds," each a `kind` string on a problem record `{ concept, subject, kind, detail }`:
   - `wrong-direction-membership` — a ConceptHeader with an **outgoing** `HAS_ELEMENT` edge (headers are never containers). Incoming memberships on headers and supersets are sound; superset↔superset membership is sound in either role. This is precisely the falsified suspicion, encoded.
   - `membership-declaration-mismatch` — an element row where the membership edge and the element's z-tag declaration disagree (edge without z-tag, or z-tag without edge — the reinstall-return signature).
   - `property-record-drift` — the primary-property `property` section disagrees with the schema's concept-object schema on **key set, required list, or per-key type** (comparison on those dimensions only — cosmetic description differences are not defects).
   - `machinery-incomplete` — a missing expected edge on the header: exactly one outgoing `IS_THE_CONCEPT_FOR` to a `:Superset`; incoming: the six `IS_THE_*_FOR` machinery edges and the universal `concept-header-superset` membership.
   - `unreadable-record` — goal concept only: an element `parseGoalRow` classifies out (the shared core is the single classification truth — handoff-binding; the check and the Goals view can never disagree).
   `detail` names the specific structure and problem in one sentence (AC 4). Problems are deterministically ordered (concept, kind, subject) so two runs on an unchanged graph return identical output (AC 1).
3. **Check queries:** directed and parameterized, never `/neighbors` (its direction-erasure caused the false inventory this story corrects). Three per concept: (a) header edge inventory in both directions with labels; (b) element consistency — full outer comparison of superset-walk membership (0001's `EXPLICIT_CYPHER` shape) against z-tag declaration (`IMPLICIT_CYPHER` shape), returning edge/tag presence per element plus the json tag for classification; (c) schema + primary-property json fetch. Cores classify; the route only fetches and assembles.
4. **Reconcile primitive:** `POST /api/normalize/reconcile-primary-property` in `src/api/normalize/index.js`, registered in `registerNormalizeRoutes`. Body `{ concept: "<name>" }` (the `save-schema` lookup idiom, `:1906-1916`). Explicit in-handler gate (`isOwner(req) || req.localTrusted` — the `relationships.js` template; note `save-schema` itself predates that discipline and is not retrofitted here). Behavior: resolve header, schema node, and primary-property node by name (loud `success:false` naming any missing node); parse the schema's single concept-object (`jsonSchema.properties[<key>]` where `<key>` is the schema's sole top-level required key — any other shape is a loud error, no write); derive the target `property` section per the create-concept convention (`:1403-1413`): same `key`, `title`, `type: 'object'`, `required` mirrored, per-property definitions stripped to `{ type }`. Compare against the current `property` section on key set + required + per-key type: equal → `{ success: true, result: 'already-consistent' }`, no write; different → replace only the `property` section (the `word` and `primaryProperty` sections pass through verbatim), `regenerateJson(ppUuid, wrapper)`, → `{ success: true, result: 'reconciled', properties: { before: [...], after: [...] } }` plus the one-line firmware-overwrite `note` on graph-changing success (relationship-primitives convention; for firmware-seeded concepts reinstall would clobber the reconciled node — documented at point of use, installer untouched).
5. **Cleanup of the live instance** is an operational step at implementation, journaled in the story's Deviations (story 1's `save-schema` precedent): one `reconcile-primary-property` call for `tapestry owner goal`, then `GET /api/brain/hygiene` read back **green** — read-back, not response success, is the assertion (the `publishToStrfry` silent-drop bug remains open on the normalize surface; same mitigation as 0001). The project concept is verified clean live; the H-class check asserts it stays green with `already-consistent` semantics available if ever needed.
6. **AC 2/AC 5 verification shape:** the four adjudicated edges (two superset-side incoming, two header-side `concept-header-superset` memberships) are asserted **present** after implementation by directed Cypher in the H suite; the goal set is asserted unchanged across the reconcile by comparing `GET /api/brain/goals` output before/after (name/statement/origin/capturedOn per goal). The reconcile structurally cannot touch elements — it writes one core node's json tag — and the H assertion proves it behaviorally.

## Consequences

- **Enables:** a green/red hygiene answer on demand from any deployment (`hygiene check green` — PRD §10); a drift fix that is repeatable at story 3's schema extension and at every fresh bootstrap; the defect taxonomy in one pure module stories 3–8 can extend (new kinds land as new classifier functions + U rows).
- **Constrains:** the brain module stays read-only — any future brain-side mutation must justify its own ADR against 0001's separation; the check's soundness definition is edge-direction-aware by construction, so future class-thread changes (e.g., story 3 edge materialization via the whitelist-extension path) must update the taxonomy deliberately, not accidentally.
- **Debt / follow-ups:** (a) Option C (save-schema folds in reconciliation) deferred to story 3's ADR — until then every schema extension needs a paired reconcile call, which the check will catch if forgotten. (b) `set-json-tag` remains an ungated generic mutation on the normalize surface — pre-existing, flagged for the security follow-up (intake 2026-07-21), not touched here. (c) The check covers the two work-item concepts only; graph-wide hygiene is a possible later epic once firmware-governed concepts have a protection story.
- **Firmware reinstall required?** **No.** No concept definitions change; both concepts are runtime-created and untouched by install passes; the reconciled primary-property node is not firmware-managed.

## Implementation notes

- File: `src/lib/brain/hygiene.js` — **new**, pure CJS, requires only `./goals`. Exports ≈ `classifyHeaderEdges(rows)`, `classifyElementConsistency(rows, parseRecord)` (takes `parseGoalRow` for the goal concept, `null` → skip record classification for the project concept), `comparePropertyRecord(schemaObj, propertySection)`, `assembleReport(perConceptResults)` → `{ sound, problems, checked }` with deterministic ordering. No fetch, no Neo4j imports — rows in, verdicts out.
- File: `src/api/brain/index.js` — add `handleGetHygiene` + route `app.get('/api/brain/hygiene', …)` in `registerBrainRoutes`. Import surface grows by exactly `require('../../lib/brain/hygiene')` — otherwise unchanged (S-class re-pin is the Tester's lane).
- File: `src/api/normalize/index.js` — add `handleReconcilePrimaryProperty` near `handleSaveSchema` (shared lookup idiom, `regenerateJson` reuse) + registration in `registerNormalizeRoutes`. In-handler gate first; loud named precondition failures; discriminated results per decision 4.
- Cypher: header inventory `MATCH (h:NostrEvent {uuid:$headerUuid})-[r]->(t) RETURN type(r), t.uuid, labels(t)` + the incoming twin; element consistency as a full outer join of the 0001 explicit/implicit arms returning `{uuid, name, createdAt, json, hasEdge, hasZTag}`; all parameterized.
- **Untouchables:** `src/api/normalize/relationships.js`, `src/api/normalize/probe.js` (byte-pinned), `src/middleware/auth.js` (incl. `PUBLIC_MUTATIONS`), `firmware/`, the four ADR-0015 `LEGACY_*` files, `ui/` (no owner-facing surface in this story — design guide do-not-design list).
- Test-class guidance (Tester's lane to specify): U = hygiene core over synthetic rows covering every kind in decision 2 plus the sound/absent/nothing-to-check states and report determinism; S = purity of `hygiene.js` (requires only `./goals`), brain import-surface re-pin, gate presence in both new handlers, no hardcoded 64-hex pubkey, byte-pins on untouchables; H = live green check (`sound: true`, zero problems, both concepts present), reconcile idempotency (`already-consistent` on second call), AC 2 edge-presence assertions, AC 5 goals-set equality across a reconcile call, host-side 403 on both new routes. A throwaway fixture concept (create → drift → detect → reconcile → teardown) is the optional H-class path for live AC-4 coverage; story 1's fixture teardown (orphan tag nodes) is the cautionary precedent — U-class synthetic rows are the primary AC-4 coverage either way.
- Full `npm test` runs ~24 min — background it from the start (OPEN.md row 83); new suite registers in `test/test.js`'s **live** gating chain before the severed terminator (OPEN.md #43).

## Out of scope

- Folding primary-property regeneration into `save-schema` (Option C — story 3's ADR decides).
- Gating or hardening `set-json-tag` and the wider authenticated-non-owner surface (pre-existing, separately tracked).
- Any UI surface, any strfry-router change, any installer change, any whitelist change.
- Graph-wide hygiene beyond the two work-item concepts.
- Fixing the `publishToStrfry` silent-drop bug (mitigated by read-back assertions, as in 0001).
