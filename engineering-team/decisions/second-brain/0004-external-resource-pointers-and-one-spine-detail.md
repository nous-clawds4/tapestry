# ADR 0004: External Resource as a runtime-created pointer concept; record-based goal↔resource linkage; freshness derived in a pure core; a per-goal detail endpoint for the one-spine Goal page

**Status:** Accepted
**Date:** 2026-07-23
**Story:** `engineering-team/stories/second-brain/4-attach-the-world.md`
**Builds on / supersedes:** second-brain ADR 0003 — fulfils d11's scheduled "per-goal read endpoint" and supersedes its interim "no new API; the detail page selects from the list read" with `GET /api/brain/goals/:slug` (0003 d11 named story 4 "the natural moment for a per-goal endpoint"; ADR 0003 Out-of-scope line 105 assigns it here). ADR 0003's header gains the reciprocal `**Amended by:**` pointer in this story's diff (body untouched — the repo's 0027/0028/0029 convention). ADRs 0001 (adopt element machinery; read seam; derived-not-stored standing; record-based structure) and 0002 (read-only brain module; taxonomy changed deliberately) remain binding.

## Context

The story (`4-attach-the-world`, gate-approved 2026-07-23): a goal points at external resources — file, vault note, nostr event, repository, web address — each with a title, a locator, optional why-kept and keywords, a noted-on and a last-verified date; a pointer card shows kind + title (opening the resource in its native home, never embedded) + a locator preview + a freshness line; freshness (`current`/`stale`/`unreachable`) is derived from verification age and the last verify outcome; verifying a resource updates its last-verified date; and the existing minimal Goal detail grows into the one-spine page — intent, then pointers, then the goal's append-only record entries. Gate rulings baked into the story: **attach and verify are conversation/owner-gated writes** (no new UI form); **verify is an asserted re-check with no outbound network egress**; the **record-entries rendering + append-only contract ship now**, live-empty until story 5's producers.

Facts established at architecture recon (live instance + source, 2026-07-23; TA `11f23fe4…` runtime-resolved throughout; adversarial map run before this gate):

- **External Resource does not exist on the graph** (`GET /api/concept-graph/summaries` — 0 hits for resource/pointer/external). It is a **net-new concept**, runtime-created (never firmware-seeded), following the pointer-element pattern (PRD §6, §7.8).
- **The pointer-element pattern to mirror is story 3's `parent` slug** (`src/api/normalize/index.js:2249` writes `section.parent = parentSlug`; `src/lib/brain/goals.js:49` parses it; `resolveDecomposition` `goals.js:143-193` dereferences it by a slug index — a pure grouping, no graph walk). The tag concepts (`profile-tags`, `event-tags`) instead use materialized wire tags (`#a`/`#p`/`#e`) — **not** the record-field idiom the PRD points at. `HAS_SUBGOAL`-style edges remain frame-excluded (whitelist extension is the relationship-primitives book's post-book path; ADR 0003 d2/Out-of-scope).
- **`create-element`'s mint idiom** (`normalize/index.js:1850-1879`): d-tag `dtag.childDTag(name, headerUuid, nonce?)`, tags `['d',dTag]['name',trimName]['z',headerUuid]['json',…]`, `signAndFinalize({kind:39999})` → `publishToStrfry` → `importEventDirect` → `SET n:ListItem, n.slug` (slug read from the json's non-`word` section) → `MERGE (superset)-[:REL.CLASS_THREAD_TERMINATION]->(elem)`. The goal-write primitives (`createChildGoal` `:2217-2272`, `updateGoalIntent` `:2315-2358`) reuse exactly this, adding validation before any write, a `name-collides` refusal, and the `serializeGoalWrite` mutex (`:2128-2133`).
- **`x-tapestry.unique` is advisory only** — no server code enforces it (`normalize/index.js`; ajv is client-side/display-only, `ui/src/pages/concepts/ElementDetail.jsx:183-202`). Uniqueness must be enforced by the write endpoint that cares (story 3's `create-child-goal` does its own `name-collides` refusal, `:2230-2242`).
- **`create-concept` (`:1183-1752`) is non-destructive on re-call:** an existing (name, TA-pubkey) returns HTTP-200 `{success:false, error:"…already exists (uuid:…)"}` — no throw, no overwrite (`:1200-1210`). A lazy-ensure must read that as "already bootstrapped."
- **`save-schema` (`handleSaveSchema`, `:1899-1997`) is fully idempotent and folds the primary-property reconcile** (ADR 0003 d8): after `regenerateJson(schemaUuid,…)` it calls `reconcilePrimaryPropertyForConcept` and returns `primaryProperty:{result: reconciled|already-consistent|not-applicable|error}` (`:1972-1991`). **The fold requires the schema to have exactly one top-level `jsonSchema.properties` key** (`:2049-2057`) — a single concept-object wrapper (`properties.tapestryOwnerGoal`; for us `properties.externalResource`) whose `.required` is mirrored into the pp node.
- **Gating for `/api/normalize/*` (`src/middleware/auth.js:304-476`):** owner session → allowed; direct-loopback (`req.localTrusted`, `:317-338`) → allowed; authenticated non-owner → 403 (`:397,417-437`); unauthenticated remote → 401 (default-deny, `:441-457`; `PUBLIC_MUTATIONS`=`['/api/neo4j/query','/api/strfry/publish']` — normalize is not public). `create-concept`/`create-element`/`save-schema` carry **no** in-handler gate (middleware only); the goal-write primitives **re-assert** `isOwner(req)||req.localTrusted` — the new resource writes will re-assert too.
- **The brain read module is read-only and its import surface is triple-pinned to five require specs** (story-1 S2 `capture…test.js:331`, story-2 S3 `structures…test.js:451`, story-3 S1 re-pin); story-2 S6 forbids mutation/strfry tokens (`…test.js:486-493`). Its read pattern for a concept's elements is the ConceptElements EXPLICIT (superset downward walk) ∪ IMPLICIT (`z`-tag) union, deduped by uuid (`src/api/brain/index.js:42-57,69-79`); an absent concept answers empty, never errors (`:18-19`).
- **The Goal detail landing zone** (`ui/src/pages/brain/GoalDetail.jsx`): reads `useBrainGoals()` (whole list), selects by slug (resolver-consistent, `:25-35`), renders the intent block ending at the hint (`:104-126`); route `goals/:slug` already registered (`ui/src/App.jsx:206`). The tree (`Goals.jsx`) renders rows without a pointer count (story-3 review: "pointers are story 4"). `useBrainGoals` (`ui/src/hooks/useBrainGoals.js`) is the fetch/poll/refetch pattern to mirror.
- **Binding copy** (style/design guides, wireframes §2): freshness `verified N days ago` (current, muted) · `not verified in N days` (stale, `--orange`) · `unreachable at last check` (`--red`); pointer empty state `Nothing attached yet — resources this goal needs will appear here.`; kind markers `file / vault / event / repo / web` (0.75rem uppercase muted, no icons); record-entry type words `proposed / approved / skipped / worked / noted`, chronological, **no edit affordance ever**; standing/freshness carried by the word, color reinforcing; **no new tokens**.

Binding prior ADRs: second-brain 0001, 0002, 0003; relationship-primitives 0001/0002 (whitelist untouched); event-tagging 0002 (never `publishEverywhere`) and 0009 (derive at read; no stored subjective flags); security-auth-exposure 0001/0002 (explicit gates on new mutations); test-hermeticity 0001 (U/S/H); ADR 0015 (legacy files untouched).

## Options considered

### Option A — New runtime-created External Resource concept; the resource record carries its goal slug; freshness derived in a pure `resources` core; two gated/serialized write primitives; a per-goal `GET /api/brain/goals/:slug` detail endpoint; the list read gains a pointer count

External Resource is a new concept minted at runtime, self-bootstrapping on first use. Each resource element's json (`externalResource` section) carries `goal` = the goal's json slug — the pointer-element idiom (story 3's `parent`), dereferenced at read by grouping, never an edge. A new pure core `src/lib/brain/resources.js` parses resource rows and derives freshness (parallel to `deriveStanding`). `create-resource` and `verify-resource` land in normalize beside the goal-write primitives, gated and serialized through the existing `serializeGoalWrite`. The one-spine page reads a new per-goal endpoint (0003 d11's scheduled move) returning intent + pointers + records; the list endpoint gains `pointerCount` for the tree row. The brain module stays read-only, gaining one require (`resources`) — a planned re-pin of the triple-pinned import surface.

- **Pros:** honors every invariant by construction — record-based linkage (0001/0003; survives export/restore and second-operator bootstrap), read-only brain module (S6 intact; S2/S3/S1 re-pinned positively), writes beside the machinery they ride (0002/0003 precedent), freshness derived-not-stored (PRD §6; event-tagging 0009), refusals as system behavior (security 0001/0002); the (goal, locator) identity closes the same silent-overwrite hazard 0003 closed for goals and lets the agent verify by the natural key it already holds; self-bootstrap makes a fresh instance work with zero manual steps (§5.9); the per-goal endpoint is exactly what 0003 d11 scheduled and keeps the list read lean.
- **Cons:** a second net-new-concept bootstrap path (mitigated: idempotent, self-healing via the d8 fold); two more normalize endpoints on an already-large module; ~30 lines of concept-lookup Cypher mirrored from `create-element`/`createChildGoal` (accepted, as 0003 accepted it); the detail endpoint re-reads all goals to resolve parent/standing context for one goal (small corpus; query-time by design — invariant #3/#4).

### Option B — Materialize a `HAS_RESOURCE` (or reuse a relationship) edge from goal to resource

Wire the goal→resource link as a typed graph edge and walk it for the detail read.

- **Cons (dispositive):** requires extending the relationship-primitive whitelist — the relationship-primitives book's post-book path, needing its cardinality-safety design first (PRD §7.9; ADR 0003 d2/Out-of-scope; the story's own Out of scope). Edges are not durable intent (PRD §6 puts the pointer in the record) and would not survive export/restore (story 8) or second-operator bootstrap. Rejected without reaching pros — same disposition ADR 0003 gave the `HAS_SUBGOAL` option.

### Option C — Attach/verify via the raw `create-element` + `save-element-json` escape hatches; validate in the conversational agent

- **Pros:** fewest new endpoints.
- **Cons:** the story's "missing kind/locator/title is refused" and the (goal, locator) dedup become agent goodwill, not system behavior; builds the contract on the **ungated, validation-free** `save-element-json`/`set-json-tag` hatches (flagged security debt, ADR 0003 Consequences (a)); the silent-overwrite hazard stays open on the blessed path; refusals untestable as system behavior; verify has nowhere to enforce the asserted-re-check semantics. Rejected, same as ADR 0003 Option C.

## Decision

We chose **Option A**.

Sub-decisions, each binding:

1. **External Resource concept (new, runtime-created).** Concept name **`tapestry external resource`** → slug **`tapestry-external-resource`** → header handle `39998:<TA>:tapestry-external-resource` (TA runtime-resolved, never hardcoded — house rule). Single concept-object wrapper `jsonSchema.properties.externalResource` (satisfies the d8 fold's one-top-level-key requirement). Record fields (json `externalResource` section): `name` (= the resource **title**), `slug` (derived — d3), `description` (machinery baseline — the title, or why-kept when present), `locatorKind` (one of the enum below), `locator` (string), `goal` (the pointing goal's json slug — d2), and optional `whyKept`, `keywords` (list), `notedOn` (ISO date), `lastVerified` (ISO date), `lastVerifyStatus` (`reachable`|`unreachable`). **`required`: `['name','slug','description','locatorKind','locator','goal']`**; `x-tapestry.unique: ['slug']` (advisory — enforcement is d3). **Locator-kind enum (canonical, stored): `file` · `vault-note` · `nostr-event` · `repository` · `web-address`** (the UI maps these to the design guide's short markers `file/vault/event/repo/web` — d10). All schema property descriptions are plain-language (the fold mirrors `required` into the pp node).
2. **Record-based goal↔resource linkage.** The resource record carries `goal` = the parent goal's json slug (the story-3 `parent` idiom). Reading a goal's pointers = read all External Resource elements and group by `goal` slug — a pure grouping in the core, **no edge, no whitelist change**. **One goal per resource in v1** (the same asymmetry as decomposition); the same locator may be attached to two different goals (two records); read-tolerant — a resource whose `goal` slug matches no goal simply renders under nothing (orphaned, harmless), mirroring dangling-parent tolerance.
3. **Resource identity = (goal, locator); the write path is the enforcement point.** A resource's identity within the brain is the pair **(goal slug, locator)** — title-independent (titles are free labels that may repeat) and **verify-stable** (re-verifying the same resource must target the same element). The Implementer composes a deterministic identity string from `goal`+`locatorKind`+`locator`, derives the json `slug` and the d-tag base from it via the existing `dtag` helpers (the ADR 0003 d2 rule "json slug ≡ d-tag base" holds, using `dtag.slug`'s diacritic-stripping variant), so two different (goal, locator) pairs get distinct uuids and re-verifying reuses the same uuid (a MERGE-in-place, not a new element). Because `x-tapestry.unique` is advisory, **`create-resource` enforces uniqueness itself**: a duplicate (goal, locator) is refused (`resource-exists`) with nothing written — closing, on this path, the same silent-overwrite hazard ADR 0003 closed for goals.
4. **Freshness derivation in a new pure core** `src/lib/brain/resources.js` (dependency-free CJS, the `goals.js` precedent): `parseResourceRow(row)` (whitelisting parser → `{uuid,name,slug,title,description,locatorKind,locator,goal,whyKept,keywords,notedOn,lastVerified,lastVerifyStatus,createdAt}`; non-resource/malformed rows → `null`, never throws); `deriveFreshness(record, nowMs)` → **`unreachable`** when `lastVerifyStatus === 'unreachable'`, else **`stale`** when `daysSince(lastVerified) > STALE_AFTER_DAYS`, else **`current`**; a companion `freshnessDays(record, nowMs)` (integer days since `lastVerified`, so the API and UI never drift on the "N"); and a grouping/count helper keyed by `goal` slug. **Freshness is derived at read time on every call, stored nowhere** (PRD §6; event-tagging 0009). `nowMs` is a parameter (pure/deterministic for U-tests; the handler passes the real clock).
5. **Read surface.**
   - `GET /api/brain/goals` (list, extended additively): each goal projection gains **`pointerCount`** — the count of resources whose `goal` slug equals this goal's slug. Existing keys unchanged (story-1/2/3 H snapshots read named fields — additive keys are safe).
   - **`GET /api/brain/goals/:slug`** (new; `handleGetGoalDetail`): gate `isOwner(req)||req.localTrusted` → 403; resolve TA; read+resolve all goals (reuse `resolveDecomposition`/`sortGoals`) and select the slug's resolver-winner (oldest `createdAt`, uuid tie-break — the same truth the tree and current page use); read that goal's resources, derive freshness; return `{success:true, goal, pointers, records}` where `goal` is the list projection **plus `parentSlug`/`parentName`** (resolved server-side, so the page needs no whole-list fetch), `pointers` is the goal's resources each with `freshness`+`freshnessDays` (sorted newest-`notedOn` first), and **`records` is `[]`** (shape established; producers are stories 5–7). An unknown slug returns `{success:true, goal:null, pointers:[], records:[]}` (the page's not-found branch) — an empty state, not an error.
   - Both reads use the ConceptElements EXPLICIT ∪ IMPLICIT pattern on the External Resource header and are **tolerant of the concept being absent** (returns empty — a fresh instance with no attach yet). Freshness is derived server-side.
   - The brain module gains exactly one require — `require('../../lib/brain/resources')` — the **sixth** spec; S6's mutation/strfry ban stays green (read-only). This trips the triple-pinned import surface → a planned positive re-pin of story-1 S2, story-2 S3, and story-3 S1 to six specs (d11 test guidance).
6. **Write primitive `POST /api/normalize/create-resource`** (in `src/api/normalize/index.js`, beside the goal-write primitives, registered in `registerNormalizeRoutes`): gate first (`if (!isOwner(req) && !req.localTrusted) return 403` — the goal-write idiom). Body `{goal:<slug>, title, locatorKind, locator, whyKept?, keywords?}`. Validation before any write: 400 for missing/empty `goal`/`title`/`locator`; refusal `unknown-kind` if `locatorKind ∉` the d1 enum; resolve the goal (the goal concept lookup; refusal `goal-not-found`/`ambiguous-slug` — a pointer must attach to a real goal); refusal `resource-exists` if the (goal, locator) already exists (d3). Then **`ensureResourceConcept()`** (d8), and mint the element with the `create-element` idiom into `{ externalResource: section }` where `section` sets `notedOn = lastVerified = today`, `lastVerifyStatus = 'reachable'`, absent optionals omitted (not empty strings). Discriminated result `{success:true, result:'attached', resource:{slug, goal, title, locatorKind}}`; refusals loud, named, HTTP-200 `{success:false, refusal, error}`, nothing written.
7. **Write primitive `POST /api/normalize/verify-resource`** (same file, same gate idiom): body `{goal:<slug>, locator, reachable?}` (default `reachable:true`). Locate the resource by (goal, locator) → refusal `resource-not-found` if absent. Read its json, set `lastVerified = today` and `lastVerifyStatus = reachable ? 'reachable' : 'unreachable'`, shallow-merge (all other sections/fields pass through verbatim), `regenerateJson`. **This is an asserted re-check** — the owner or a session attests to the resource's state; the handler **never fetches, crawls, or pings** the locator (no outbound egress; PRD §7.4). Discriminated result `{success:true, result:'verified', resource:{slug, freshness}}`. (Overwriting `lastVerified`/`lastVerifyStatus` is a **durable-intent** update, like ADR 0003 d7's deliverable/boundary sharpening — the append-only constraint governs the **record entities** (Work Record/Proposal/Priority Signal), not resource metadata.)
8. **Self-bootstrapping concept provisioning `ensureResourceConcept()`** (module-internal, idempotent): resolve the External Resource header; if present, return. If absent: `create-concept` (name `tapestry external resource`) treating the "already exists" response as success; then `save-schema` with the complete d1 schema (which auto-reconciles the primary property via the d8 fold in the same call); return. **create-concept/save-schema run only when the concept is absent** — after the first attach the ensure is a cheap existence check, so there is **no per-write churn** (save-schema re-signs the schema node, so it must not run on every attach). Runs inside the write path's loopback/owner gate (`req.localTrusted` on server-side calls). This honors §5.9 (the empty brain self-provisions, nothing baked in) and makes the H-suite self-contained on any instance. **Never firmware-seeded** (PRD §7.8); the first-run bootstrap outcome is journaled at implementation for transparency.
9. **Serialization.** `create-resource` and `verify-resource` run their read-validate-write bodies through the **existing** `serializeGoalWrite` chain (`normalize/index.js:2128-2133`) — **not renamed** (story-3 S5 pins its presence): one process-singleton write queue serializes all brain mutations, so attach/verify (and any concurrent goal write) never interleave a read-validate-write race (a duplicate-(goal,locator) attach racing itself, or verify racing attach, is closed in-contract). `ensureResourceConcept` runs inside the serialized body on the first attach.
10. **UI — the one-spine Goal detail + the tree pointer count.**
    - **`ui/src/pages/brain/GoalDetail.jsx`** switches its data source to a new hook **`useBrainGoalDetail(slug)`** (mirrors `useBrainGoals`' fetch/poll/refetch/AbortController shape, against `/api/brain/goals/${slug}`) returning `{goal, pointers, records, loading, error, refetch}`. The **intent block is unchanged** (name, meta line — now using the endpoint's `parentSlug`/`parentName` — statement, **Done means:**/**Stays inside:**, hint on captured leaves). **Below it, in wireframe §2 order:** a **pointers** section and a **record entries** section.
    - **Pointer card** (a `PointerCard` component or inline): kind marker (map `locatorKind`→`file/vault/event/repo/web`, uppercase-muted typography, no icons) · **title** as an accent link that **opens the locator in its native home** (`target="_blank" rel="noopener noreferrer"`; http(s) for web/repository, a nostr scheme/`njump` for nostr-event, a file/path reference for file/vault-note — register-safe, Implementer's exact scheme) — **no iframe, no embed, no fetch of the resource** (AC3) · **locator preview** (truncated middle, monospace muted) · **freshness line** composed from `freshness`+`freshnessDays`: `verified {N} days ago` / `not verified in {N} days` / `unreachable at last check`, colored `--text-muted`/`--orange`/`--red` by word · optional **why-kept** as one italic line. Empty state verbatim: `Nothing attached yet — resources this goal needs will appear here.`
    - **Record entries** section: renders `records` chronologically — each entry a date (muted, absolute) · type word (`proposed/approved/skipped/worked/noted`) · one-sentence summary — with **no edit or delete affordance on any entry** (no button/input/onClick-edit at the entry level). Live-empty in story 4 (an empty section, no error); the append-only contract is the enforced invariant.
    - **`ui/src/pages/brain/Goals.jsx`**: each row gains the design-guide pointer count as text (`{n} pointer{n===1?'':'s'}`) from `g.pointerCount`, rendered only when `> 0`. Disclosure/standing/hint rendering unchanged (story-1 S5b/S7 identifiers untouched).
    - **No new tokens** — freshness colors reuse `--orange`/`--red`/`--text-muted`; new `.brain-*` classes (pointer card, kind marker, locator preview, freshness line, record entry) extend the existing block; token vars only.
11. **Copy discipline.** All new owner-facing strings (kind markers, freshness lines, empty state, any record-entry chrome) come verbatim from the guides and pass the banned-jargon scan (*element, kind, schema, event, pubkey, superset, concept header, persona, acceptance criteria, lease, payload, endpoint*) — note `event` is banned as owner-facing text, so the nostr-event kind renders as the marker **`event`**… which is the design-guide marker; the scan must whitelist the design-guide markers exactly, or assert on the specific strings (Tester's call). No exclamation marks. Extend story-3's `GoalDetail` jargon scan (S9) to cover the new strings.
12. **Conversational contract addendum** (ADR 0001 d1 / 0003 d12 grow; story 5 makes it agent-discoverable): attach a resource — `POST /api/normalize/create-resource` (d6 body); verify a resource — `POST /api/normalize/verify-resource` (d7 body). The agent reads goals/slugs from `GET /api/brain/goals`, targets pointers by (goal, locator), and utters the one-sentence confirmations itself (register-conformant; API responses are never owner-facing).
13. **Freshness threshold.** `STALE_AFTER_DAYS = 30` — a single named constant in `resources.js`, tunable in one place; **not per-kind in v1**. Rationale: a month balances "fresh enough" against nagging; the wireframe's 3-days-current and 40-days-stale both fall correctly across it. The freshness **wording** is fixed regardless of the threshold.

## Consequences

- **Enables:** every goal carries its own working set with at-a-glance freshness; the one-spine Goal detail (intent + pointers + record) ends cross-surface story assembly (design guide principle 3); a validated attach/verify contract the conversational agent can trust (refusals are system behavior); a per-goal read endpoint (0003 d11 realized) that later stories extend (records populate it; a pointer-produced-by-work-record links resource↔work in story 5); a self-provisioning concept that works on a fresh second-operator instance with no manual step.
- **Constrains:** the goal↔resource linkage is record-based — any future edge materialization must supersede this ADR **and** go through the relationship-primitives whitelist path; one goal per resource, and one resource per (goal, locator), in v1 (re-attaching the same locator elsewhere is a new record; sharing one record across goals is a later decision); the brain module stays read-only (resource **writes** live in normalize); `save-schema`'s per-concept effect is unchanged from ADR 0003 (the bootstrap calls it once, when absent).
- **Debt / follow-ups:** (a) External Resource is **not yet covered by the hygiene check** (`HYGIENE_CONCEPTS` stays the two work-item concepts) — a `dangling-resource-goal-reference` / duplicate-slug classifier for resources is a natural later addition; the read path is already tolerant. (b) No **edit/detach/retire** flow for a resource (only append-only verify) — corrections are new facts (PRD §7.2); a retire/detach story is deferred (the style guide's "mark it retired" copy anticipates it). (c) The raw `save-element-json`/`set-json-tag` hatches can still write unvalidated resource fields — pre-existing flagged debt, compensated by read-time tolerance. (d) ~30 lines of concept-lookup Cypher mirrored from `create-element`/`createChildGoal` — accepted, as ADR 0003 accepted it.
- **Firmware reinstall required? No.** The concept is runtime-created (self-bootstrapped); the installer is untouched; the d8 fold's install-time reach is unchanged from ADR 0003.
