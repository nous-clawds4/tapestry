## Design-note ratification (in lieu of an ADR)

**Ratified.** The story's design is the design of record for this change.

- **The chosen approach holds.** One pure, zero-require merge library (`src/lib/treasureMapMerge.js`) that both generators and the suite consume directly; one fetch module (`src/api/export/nip85/currentMap.js`) with injected seams whose defaults are story 4's `scanLocal` / `fetchFromRelays`; both generators call fetch → rows → template and report what the merge did. Every element of the note is in the diff at the named path with the named signature (`mergeTreasureMapTags(existingEvent, freshRows) → { tags, preserved, regenerated }`; `restampTreasureMap(existingEvent, now)`; `fetchCurrentMap(pubkey, deps) → { event, where }` throwing on a lookup error), and the eleven rows are one shared constant.
- **The rejected alternatives are real.** Two in-generator copies is exactly how the defect had two homes — at `7c0225c4` the eleven-row literal existed twice, byte-identical, in `bin/brainstorm-create-kind10040.js` and the API handler, and neither read the current Map. Merging at publish is too late by construction: both publish paths receive an already-signed event and verify its signature before forwarding (`brainstorm-create-and-publish-kind10040.js:88-100`; `publish-signed-kind10040.js:59-68`); any merge there would invalidate the signature.
- **The blast radius is as stated, plus one line the note did not name.** Two generator files, one new lib, one new fetch module — and the additive `{ strict }` option in story 4's module (Deviation 1), which the Implementer recorded. No UI, no publish path, no 10040 reader, no `package.json`, no protocol/firmware file.
- **Two places where the implementation is wider or narrower than the note's words, both acceptable and now recorded here:** (i) the default relay set is a superset of "the NIP-85 home relay + `settings.aRelays`' general group" — it also includes `aTrustedAssertionRelays` (`currentMap.js:24`), the group the Treasure Map page's relay-presence feature already treats as where a Map lives; more places to look means fewer blind regenerations, so this is the right reading of AC-5's "relays the export flow already knows". (ii) The seams' notion of "error" is what they *throw*: a hung/timed-out leg, a strfry that cannot be spawned, or a pool that throws — not a strfry that exits non-zero with empty stdout, and not relays that refuse the connection (Non-blocking 1–2). AC-5's guarantee therefore holds for the cases the seams surface; the residual is a double fault (both legs silently empty while a Map exists) whose fix belongs in the seams, not in this diff.

### Non-blocking
1. **`src/api/dlist-curation/index.js:151-169` (the strict relay leg) with `src/api/export/nip85/currentMap.js:46`** — `{ strict: true }` rethrows only what `pool.querySync` rejects or what the 8 s race rejects (`:157-160`). In nostr-tools 2.10.4 a per-relay connection failure is not a rejection: `subscribeMany` catches the `ensureRelay` error and records it as that relay's close reason (`node_modules/nostr-tools/lib/cjs/pool.js:651-656`), `onclose` fires once every relay has closed (`:624-631`), and `querySync` then resolves with whatever arrived — possibly nothing (`:686-699`). So "every relay refused the connection" reads as `where: 'none'`, not as an error, and the generator proceeds. Reachable only as a double fault (local strfry has no copy **and** the relays are all unreachable **and** a Map exists on them) — on the deployments that matter the router preset streams kind 10040 into local strfry and the Treasure Map page syncs it, so the local leg is the one that carries the weight, and the diff is strictly safer than the always-blind behavior it replaces. Optional follow-up (a candidate OPEN.md row; story 4's module, not this diff): in strict mode drive `subscribeManyEose` directly and throw when every close reason is a connection/`CLOSED` error rather than an EOSE close, so that AC-5's "a relay error refuses" also covers a fast refusal.
2. **`src/api/dlist-curation/index.js:121-144` (`scanLocal`)** — rejects on a spawn error or the 10 s timeout, but a `strfry` that runs and exits non-zero with empty stdout resolves `[]` (the exit code is never read; `:134-142`). Under `fetchCurrentMap` that reads as a local miss and falls to the relay leg (not straight to `'none'`), so a blind regeneration again needs both legs silent. Same optional follow-up: reject on a non-zero exit (with stderr in the message), at least under strict.

A product note for the book's `prd-seed.md`, not a code ask.
