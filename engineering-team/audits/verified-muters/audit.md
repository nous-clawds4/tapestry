## 1. What shipped

A fifth point-of-view-filtered profile metric — **Verified Muters** — mirroring Verified Followers, surfacing the count of *verified* users (those clearing the GrapeRank muter cutoff) who have muted the observed account, plus a list page of exactly who they are. Delivered across two stories:

- **Backend read API** — `GET /api/get-grapevine-muters` (the verified-muters list, owner/House-PoV only) and a `verifiedMuterCount` field added to the existing `GET /api/get-user-counts` response, both keyed on the same `VERIFIED_MUTERS_INFLUENCE_CUTOFF` so the count equals the list length within the read path. — `stories/verified-muters/1-verified-muters-read-api.md`
- **Profile surface** — a neutral counts-row badge ("Verified Muters") positioned after Hops and before Verified Reporters, a visual line break grouping the "bad" indicators (Verified Muters, Verified Reporters) onto their own row, and a list page at `/user/:pubkey/muters` mirroring the Verified Followers list (same columns, same default sort, no report-specific columns). — `stories/verified-muters/2-verified-muters-profile-surface.md`

- **Data & contracts:**
  - New route `GET /api/get-grapevine-muters?observee=<pk>[&observer=owner]` (`src/api/index.js`), handler `handleGetGrapevineMuters` in `src/api/grapevineInteractions/queries/mutersWithMetrics.js`. Cypher: `MATCH (muter:NostrUser)-[:MUTES]->(observee:NostrUser {pubkey:$observee}) WHERE muter.influence > $cutoff` with bound `$cutoff = VERIFIED_MUTERS_INFLUENCE_CUTOFF` (default 0.05). Returns the six Verified-Followers columns `{pubkey, influence, hops, verifiedFollowerCount, verifiedMuterCount, verifiedReporterCount}` — no report fields. Response `{ success, observer:'owner', observee, count, data }` with `count === data.length`; `observee` hex-validated → 400; non-owner `observer` → 400; `NEO4J_QUERY_TIMEOUT_MS` → 504.
  - Extended contract `GET /api/get-user-counts` (`src/api/export/users/queries/userdata.js`, `handleGetUserCounts`): payload now carries `verifiedMuterCount` beside `verifiedFollowerCount`/`verifiedReporterCount` — node-property-first read (`u.verifiedMuterCount`), count-only `:MUTES` live fallback bounded by the query deadline → `null` on timeout/error. `handleGetUserData` was **not** touched (it already returned `verifiedMuterCount` before this book).
  - The pre-existing `cypherQueries.js` `verifiedMuters` registry entry and the shared `get-grapevine-interaction` route were left untouched (shape-incompatible with the list contract; documented in ADR 0001).
