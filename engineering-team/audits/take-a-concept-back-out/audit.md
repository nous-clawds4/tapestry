## 1. What shipped

One capability, delivered whole: **the instance owner can shrink a Tapestry in place — the mirror of #5's grow.**

- From the existing Exploration page (`/tapestry/tapestries/<uuid>`), the owner of the instance can take out a member concept of a Tapestry published under their own key or the assistant's (TA's); after an explicit inline confirm, the Tapestry — same uuid, same URL, one directory row — no longer shows that concept to the owner or to any other session that opens it afterwards. `stories/done/tapestries/6-take-a-concept-back-out.md`
- **Remove-only is structural, not behavioural**: the replacement event is a verbatim copy of the live event minus exactly one authored member node and the import(s) attributed to it and claimed by no remaining member (`buildRemoveConceptDraft`, `ui/src/pages/tapestries/tapestryDraft.mjs`). Title, description, `name` tag, authored integrations, unknown tags/fields, remaining node/import order all pass through byte-identical; `created_at` is strictly newer so replacement can never tie.
- **Attribution is evidence-based, not derivation-only** (ADR 0006 Decision 2-A): an import leaves iff read-time containment ∪ options derivation ∪ short-slug derivation ties it to the removed member *and* no remaining member claims it — correct on every live event including the real `dog` divergence (member node uuid `…:b08502ed-…`, import `…:dog-concept-graph`), where slug-segment derivation alone fails. An import attributable to nobody passes through untouched.
- **A Tapestry keeps at least one concept**: at exactly one authored concept the component renders the plain-language refusal sentence *instead of any control* — no save is reachable; the pure transform independently throws the same sentence (defense in depth), counting **concepts only** (property/superset nodes don't count).
- **The affordance is owner-strict** (`canEdit`: session classified `owner` AND event author ∈ {runtime TA, session pubkey} — the renamed `canAdd`, one expression gating add and remove alike): guests, anonymous sessions, non-owner admins, and any foreign-authored tapestry get no affordance at all.
- **No new page, no new route, no new server endpoint, no new dependency** — verified in the diff (no server file; the component's only network call is the pre-existing `POST /api/strfry/publish`; `package.json` untouched); both signing branches are the shipped #3/#5 paths, deliberately duplicated rather than extracted (sentinel S3 constraint; rule-of-three recorded).

**What did not ship:** connection/integration editing, title/description editing, deletion or emptying of a tapestry, batch removal, undo/restore, ghost-member (import-only) removal, foreign-tapestry editing, any change to the add or create paths (zero lines — R1/R2-guarded), any server or firmware change, any production promotion.
